## 1. الهدف والنطاق

### 1.1 الهدف
نظام ويب مركزي يدير دورة حياة الموظف كاملة، من التوظيف حتى انتهاء الخدمة، بواجهة API مصممة من البداية لتخدم تطبيق الموبايل لاحقاً دون إعادة بناء.

- **النموذج الأول:** شركة واحدة بفروع متعددة.
- **التحويل لاحقاً إلى SaaS** عند اكتمال المشروع، وقد صُمّم ليكون ترقية وليس إعادة كتابة (`company_id` في كل الجداول، RLS، إعدادات لكل شركة).
- **اللغات:** عربي/إنجليزي مع RTL، وتقويم هجري للعرض.
- **التقنيات:** PostgreSQL، Node.js + Express، React.

### 1.2 الأدوار والصلاحيات

| الدور | الصلاحيات الأساسية |
|---|---|
| مدير النظام | الإعدادات، الأدوار، المستخدمون |
| مسؤول الموارد البشرية (HR) | بيانات الموظفين والإجازات والحضور والوثائق وإدارة القوالب |
| المدير المباشر | الموافقة على طلبات فريقه، الاطلاع على حضورهم |
| المحاسب / الرواتب | إعداد المسيّر والسلف والدفع |
| الموظف | ملفه، طلباته، قسائمه، حضوره |

**RBAC بنطاق:** يُمنح الدور على مستوى **الشركة / الفرع / القسم / الفريق / الذات**. الأدوار قابلة للتخصيص وليست ثابتة في الكود، والصلاحيات بصيغة `module.resource.action`.

### 1.3 الوحدات والمراحل

**MVP**
1. الهيكل التنظيمي: الشركة، الفروع، الأقسام، المسميات، الدرجات، مواقع العمل، مراكز التكلفة
2. ملفات الموظفين: البيانات الشخصية، جهات الاتصال، المعالون، الحسابات البنكية، العقود، التاريخ الوظيفي
3. **الأرشيف العام** للوثائق بحقول ديناميكية (موظف / شركة / فرع) مع تذكيرات
4. المستخدمون والأدوار والصلاحيات + سجل التدقيق
5. الحضور: ورديات، جداول، عطل، إدخال يدوي / استيراد، إضافي، تصحيحات
6. الإجازات: أنواع، سياسات، دفتر أرصدة، طلبات
7. الرواتب: بنود، هياكل، رواتب، سلف وقروض، مسيّر، قسائم، **محاكاة المسيّر**
8. محرك الموافقات + الإشعارات (داخل التطبيق وبريد)
9. الوثائق الصادرة: **مدير القوالب** + شهادات ونماذج معتمدة
10. تقارير جاهزة + مركز الاستيراد والتصدير
11. OpenAPI

**بعد الـ MVP (المرحلة 2)**
- ربط **أجهزة البصمة**، ثم **تطبيق الموبايل** (تسجيل دخول مع الموقع GPS وقراءة QR ديناميكي من شاشة داخل الشركة)
- التوظيف، التقييم والأداء، التدريب
- مصمم أنواع الطلبات، قواعد الأتمتة، قوائم مهام التعيين وإنهاء الخدمة
- الأصول والعهدة، إدارة الترجمات، Push وواتساب
- **مصمم التقارير والنماذج المرئي** (مشروع مستقل)

**المرحلة 3**
- إنهاء الخدمة والمخالصة، الجزاءات والمخالفات
- مصمم لوحات المعلومات، سياسات الاحتفاظ والإخفاء
- التحويل إلى SaaS

### 1.4 المتطلبات غير الوظيفية
- **الأمان:** تشفير الحقول الحساسة، JWT مع Refresh دوّار، 2FA اختياري، RLS.
- **Audit Log** لكل تعديل، مع تسجيل **قراءة البيانات الحساسة**.
- **Soft Delete والامتداد الزمني (Effective Dating)** لتاريخ الراتب والقسم.
- **API-first** موثّق بـ OpenAPI.
- **الأداء:** فهارس، Pagination، ومعالجة الثقيل في مهام خلفية.
- **النسخ الاحتياطي والاستعادة** مع اختبار دوري، واستيراد/تصدير Excel.
- **قابلية النقل:** كل شيء في حاويات وبإعدادات خارجية.

## 2. القرارات المعمارية الكبرى

| القرار | الخلاصة | الأثر |
|---|---|---|
| نموذج الشركة | شركة واحدة بفروع أولاً، ثم SaaS | `companies` بصف واحد، و`company_id` في كل جداول بيانات الشركة |
| القواعد القانونية | قواعد الرواتب والإجازات **قابلة للضبط**، والتفاصيل القانونية مؤجلة | جداول شرائح، أسس احتساب، معادلات، كلها بيانات |
| العملات | عملة أساسية، والتعدد **حالة استثنائية** | عملة لكل سجل راتب، مسيّر لكل عملة، أسعار صرف للتقارير، وميزة قابلة للتعطيل |
| الأرقام | تخزين 4 خانات عشرية، والعرض من الإعدادات | `numeric(18,4)`، `decimal.js`، نص عشري في الـ API |
| الأقسام والفروع | القسم يرتبط بفرع واحد على الأقل (متعدد بمتعدد) | `department_branches` ومفتاح أجنبي مركّب من `employments` |
| الأرشيف | عام لكل المالكين، وبحقول يعرّفها المستخدم | `document_types` + `document_type_fields` + `documents.values jsonb` |
| الوثائق الصادرة | قوالب ملفات يرفعها HR، نموذج لكل لغة | مدير القوالب، لقطة PDF ثابتة وإصدار القالب لكل وثيقة |
| مصمم التقارير | مشروع مستقل لاحقاً | تقارير جاهزة بصيغة `manifest` موحّدة تقبل مصمماً مستقبلاً |
| التجاوز اليدوي | HR يحوّل أي نتيجة إلى يدوية موثّقة | أعلام + لقطة آلية + حماية من إعادة الاحتساب |
| الحضور | يدوي/استيراد ← أجهزة بصمة ← موبايل | `attendance_records` يفصل المصدر عن الاحتساب |
| الرواتب | شهرية، من أول الشهر لآخره، أساس 30 يوماً، بدائل قابلة للضبط | `pay_groups` بإعدادات `frequency` و`day_basis` و`calc_method` |
| بنية التطبيق | Modular Monolith، طبقات صارمة، `ctx` | حدود وحدات بـ ESLint، ومعاملة وسياق نطاق في كل عملية |

## 3. تصميم قاعدة البيانات

### 3.1 الاتفاقيات
| البند | القرار |
|---|---|
| المعرّفات | UUIDv7 |
| الأوقات | `timestamptz` (UTC)؛ والتواريخ التقويمية `date` |
| المبالغ | `numeric(18,4)` مقترنة بـ `currency` |
| الأعمدة المشتركة | `company_id, created_at, updated_at, created_by, updated_by, deleted_at`، و`version` للجداول القابلة للتعديل |
| القوائم | جداول مرجعية بدل `ENUM` |
| القواعد المرنة | `jsonb` مع `CHECK` على الأساسي منها |
| الامتداد الزمني | `valid_from/valid_to` مع `EXCLUDE USING gist` |
| الحذف | ناعم، وقيود الفرادة فهارس جزئية `WHERE deleted_at IS NULL` |
| اللغات | `name_ar`, `name_en` |
| الامتدادات | `pgcrypto`, `btree_gist`, `citext`, `pg_trgm` |
| التسمية | `snake_case`، جداول بالجمع (تفاصيلها في `CONVENTIONS.md`) |

### 3.2 العملات والأرقام والتواريخ
- **التخزين** بأربع خانات؛ **الحساب** بدقة كاملة، والتقريب عند نقاط محددة بطريقة قابلة للضبط.
- **العرض** منفصل عن التخزين:
  - `currencies`: `display_decimals`، الرمز، موضع الرمز، `rounding_mode`
  - `settings` بنطاق (شركة / فرع / مستخدم) وأولوية: المستخدم ثم الفرع ثم الشركة ثم الافتراضي: صيغة التاريخ والوقت، التقويم، أول يوم في الأسبوع، الفواصل، شكل الأرقام، المنطقة الزمنية
- الـ API يُرجع القيم الخام دائماً، والواجهة تنسّقها بـ `Intl`.

### 3.4 الجداول المحورية

**الهيكل والهوية**
- `departments`: شجرة بـ `parent_id`، **بلا `branch_id`**؛ الفروع عبر `department_branches` (فرع واحد على الأقل، يُتحقق منه في الـ Backend وبـ Constraint Trigger). إزالة فرع من قسم تُمنع إن وُجد فيه موظفون.
- `user_role_assignments`: `user_id, role_id, scope_type (company|branch|department|team|self), scope_id`.
- `refresh_tokens`: `token_hash, device_info, expires_at, revoked_at, family_id, replaced_by_id`.
- `audit_logs`: للإضافة فقط (يُسحب UPDATE/DELETE من مستخدم التطبيق)، بتقسيم شهري، وفهرس `(entity_type, entity_id, occurred_at)`.

**الموظفون**
- `employees`: `employee_no` (صيغته قابلة للضبط)، أسماء (الأول، الأب، الجد، العائلة بالعربية والإنجليزية) و`search_text` مُطبَّع، الميلاد والجنس والحالة والجنسية، الصورة، `status`، `first_hire_date`، `user_id` (فريد)، `custom_fields jsonb`. **أرقام الهوية والجواز ليست أعمدة هنا**، بل وثائق في الأرشيف.
- `contracts` (الاتفاق القانوني): النوع، البداية والنهاية، نهاية التجربة، مدة الإشعار، الحالة، ملف العقد، `terms jsonb`.
- `employments` (التعيين الإداري عبر الزمن): `employee_id, contract_id, branch_id, department_id, job_title_id, job_grade_id, manager_employee_id, cost_center_id, employment_type, work_mode (حضوري|عن بُعد|هجين), work_country, valid_from, valid_to`. `EXCLUDE` يمنع التداخل، ومفتاح أجنبي مركّب `(department_id, branch_id)` نحو `department_branches` يمنع تعيين موظف في قسم غير متاح في فرعه.
- `employment_changes`: تعيين، نقل، ترقية، تغيير مدير، إيقاف، إنهاء، مع `change_reasons`، وكل حدث ينتج صف `employments` جديداً بدل تعديل القديم.
- `employee_bank_accounts`: IBAN مشفّر، العملة، الحساب الأساسي، فترة السريان.
- الحقول الحساسة مشفّرة (AES-256-GCM) مع `key_id` وبصمة مجزَّأة للبحث.

**الأرشيف العام**
- `document_types`: الاسم، التصنيف، `owner_type` (موظف|شركة|فرع)، `is_required`، `system_key` (لما يعتمد عليه الكود، لا يُحذف).
- `document_type_fields`: `key`، الاسم عربي/إنجليزي، `data_type` (نص، نص طويل، رقم، تاريخ، مبلغ، نعم/لا، قائمة اختيار، ملف، **تاريخ تذكيري**)، إلزامي، حساس (مشفّر)، فريد، قواعد تحقق، خيارات، ترتيب، `show_in_list`، `is_active`.
- `documents`: النوع، المالك، `values jsonb`، الحالة، `version_no`، `superseded_at`. المبلغ يُخزَّن `{"amount":"1500.0000","currency":"USD"}` بنص عشري.
- `document_files`: ملفات بحقل ملف (عدة صفحات). `document_reminders`: `due_date` وحالتها، مستقلة عن JSON لسرعة المهمة اليومية؛ وإعداد الحقل التذكيري يحدد أيام التنبيه والمستلمين والتكرار.
- **لا حذف لحقل فيه بيانات** (يُعطَّل)، ولا تغيير نوعه بعد وجود قيم. رفع وثيقة جديدة يؤرشف القديمة.
- فهرس GIN على `values`، وللبحث الدقيق جدول فهرسة مكتوب الأنواع عند الحاجة لاحقاً.
- صلاحية قراءة/كتابة لكل نوع وثيقة.

**الحضور**
- `shifts`: البداية والنهاية، **تعبر منتصف الليل؟**، الاستراحة، سماح التأخير والخروج المبكر، الحد الأدنى للدوام الكامل، وردية مرنة. `shift_segments` للدوام المقسّم.
- `work_schedules` + `work_schedule_days`: نمط أسبوعي أو دوري؛ **أيام الراحة تُعرَّف هنا** لا في الكود. `schedule_assignments` بامتداد زمني.
- `attendance_records` (إضافة فقط): `employee_id, event_time, direction, source (web|mobile|device|manual|import), device_id, external_ref (فريد), lat, lng, accuracy, work_location_id, flags, created_by, reason`.
- `attendance_days` (محسوبة): الوردية، أول دخول وآخر خروج، `worked_minutes, late_minutes, early_leave_minutes, overtime_minutes`، الحالة (حاضر|غائب|إجازة|عطلة|راحة|جزئي|`incomplete`)، `leave_request_id`، `is_locked`، `inputs_hash`، وأعمدة التجاوز اليدوي. فريد على `(employee_id, work_date)`.
- `attendance_policies` و`overtime_rules` قابلة للضبط وتُسند لمجموعات.

**الإجازات**
- `leave_types`: الوحدة (أيام|ساعات)، مدفوعة ونسبة الدفع، طريقة العد (تقويمية|عمل)، الحد الأقصى المتصل، مدة الإشعار، الرصيد السالب، قصر النوع على جنس/نوع توظيف، `required_document_type_id`.
- `leave_policies`: الاستحقاق (دفعة سنوية|شهري تراكمي|حسب أيام العمل)، **شرائح سنوات الخدمة**، بداية السنة، التناسب، الترحيل وانتهاء الصلاحية، فترة الانتظار، وتُسند بامتداد زمني.
- `leave_ledger`: `entry_type` (استحقاق، استهلاك، ترحيل، انتهاء، تسوية، صرف نقدي، عكس)، `quantity numeric(8,3)` بإشارة، `effective_date`, `expires_at`, المصدر، `idempotency_key` فريد. `leave_balances` نسخة تُعاد بناؤها من الدفتر دائماً.
- `leave_requests`: من/إلى، نصف يوم أو ساعات، الكمية المحسوبة، `units_mode`/`manual_units`، المرفق (من الأرشيف)، البديل، الحالة، ومرجع الموافقة. قيد `EXCLUDE` يمنع تداخل إجازات الموظف.

**الرواتب**
- **`pay_components`**: النوع (استحقاق|استقطاع|مساهمة صاحب عمل|معلوماتي)، طريقة الحساب (ثابت|نسبة من أساس|معادلة|مبني على الحضور|بالوحدة)، `params jsonb`. **`payroll_bases`** (`GROSS`, `INSURABLE`, `TAXABLE`…) وانتماء البند لها عبر `pay_component_bases`. **`rate_tables`** جداول شرائح بامتداد زمني. بهذا تكون الضريبة والتأمينات بنوداً تشير لأسس وجداول، **فتُعبّأ التفاصيل القانونية لاحقاً كإعدادات**.
- `salary_structures` (قوالب بنود تُربط بالدرجات/المسميات)، `employee_salaries` (العملة، الأساسي، الهيكل، `salary_basis` شهري فقط حالياً، بامتداد زمني)، `employee_salary_components` (استثناءات **دائمة** لموظف).
- `pay_groups`: `frequency` (شهري)، `day_basis` (`fixed_30` افتراضي | أيام الشهر الفعلية | أيام العمل)، `calc_method` (خصم الغياب من الكامل | احتساب أيام الحضور)، `paid_non_working_days`، `round_at`. `pay_group_assignments` بامتداد زمني.
- `payroll_inputs`: مكافآت، خصومات، إضافي، بالمصدر (يدوي|استيراد|حضور|سلفة).
- `loans` و`loan_installments`: القيمة والعملة وعدد الأقساط وبداية الخصم وحالة القسط، والسداد المبكر.
- `payroll_runs`: الفترة، المجموعة، **العملة**، سعر الصرف (لقطة)، الإجماليات، `config_snapshot jsonb`، والحالة: `مسودة ← محسوب ← قيد المراجعة ← معتمد ← مقفل/مصروف`.
- `payslips`: `currency, gross, deductions, net, employer_cost`، **لقطة** (الفرع، القسم، المسمى، الحساب البنكي، أيام الحضور)، `warnings jsonb`، `calc_mode`.
- `payslip_lines`: رمز البند واسمه (نسخة ثابتة)، الكمية، المعدل، المبلغ، `source (calculated|manual|adjustment)`, `is_excluded`, `auto_amount`, و**`calc_detail jsonb`** يشرح كيف وصل الرقم.
- `payments`: حالة الدفع، الطريقة، التاريخ، `amount_paid` و`difference_reason`.

**الموافقات**
- `approval_flows`: الكيان (إجازة، سلفة، إضافي، تصحيح حضور، مسيّر، تغيير راتب…)، **شروط التطبيق `jsonb`**، الإصدار.
- `approval_steps`: الموافِق (مدير مباشر، مدير المدير، دور بنطاق، مستخدم)، النمط (أي واحد|الكل|N من)، التصعيد بعد مهلة، التخطي التلقائي، **موافق بديل إلزامي**.
- `approval_requests`: الكيان، المقدّم، **لقطة من المسار** وقت الإنشاء، الحالة، الخطوة الحالية.
- `approval_request_assignees`: لصندوق «موافقاتي» (مفهرس بـ `(user_id, status)`).
- `approval_actions` و`approver_delegations`.

**الوثائق الصادرة**
- `letter_templates`: الرمز، التصنيف (شهادات|تأديبية|قرارات|عهد|أخرى)، `requires_approval`، مسار الموافقة، `self_service_allowed`، `visible_to_employee`.
- `letter_template_versions`: اللغة، **`source_file_id` + `engine` (docx|html|xlsx) + `file_hash` + `manifest jsonb`**، الحالة (مسودة|معتمد|متقاعد)، المعتمِد، تاريخ السريان. **لا يُصدر إلا من نسخة معتمدة.**
- `template_fields`: حقول إدخال يدوية بنفس محرك أنواع حقول الأرشيف، مع نوع **جدول** (صفوف متكررة).
- `letterheads`: ترويسة وتذييل وشعار وتوقيع وختم لكل شركة/فرع. `numbering_sequences`: ترقيم قابل للضبط مثل `HR/CERT/2026/0045`.
- `issued_documents`: النموذج ونسخته، الموظف، الرقم التسلسلي، اللغة، القيم المُدخلة، **لقطة المتغيرات المحلولة**، ملف PDF، الموقِّع، الحالة (مسودة|قيد الموافقة|صادرة|ملغاة|مستبدلة)، رمز التحقق QR. **غير قابلة للتعديل بعد الإصدار**؛ التصحيح = إلغاء مع سبب وإصدار بديل.
- صفحة عامة `GET /public/verify/:token` تعرض صحة الوثيقة وبياناتها الأساسية فقط.

**التقارير**
- `reports`: الرمز، الاسم، الصلاحية، ملف القالب، الإصدار، التفعيل.
- `data_entities` و`data_fields`: **فهرس البيانات** (يُعرَّف في الكود ويُزامَن عند النشر): الكيانات والحقول بأسمائها العربية والإنجليزية ونوعها وحساسيتها وصلاحيتها. تدخل إليه الحقول المخصصة وحقول الأرشيف تلقائياً.

### 3.5 قيود تصميمية ظهرت في المراجعة الشاملة
1. `pay_group_assignments` لربط الموظف بمجموعة الدفع بامتداد زمني.
2. `cost_centers` لتقارير التكلفة، مرتبط بـ `employments`.
3. `approval_request_assignees` لسرعة صندوق الموافقات.
4. موافق بديل لكل خطوة، ومنع حلقات التسلسل الإداري.
5. `period_locks` عام (الوحدة، الفترة، من قفلها ومتى، وسجل إعادة الفتح) بدل أعلام متفرقة.
6. قفل صف (`FOR UPDATE`) على رصيد الموظف عند الموافقة، ومفتاح Idempotency لحركات الدفتر.
7. `job_runs` لتتبع المهام الخلفية.
8. فهارس فرادة جزئية مع الحذف الناعم.
9. قاعدة واضحة لتعارض الإجازة مع الحضور (تنبيه HR أو إلغاء الحضور المحسوب).
10. `search_text` مُطبَّع للعربية مع `pg_trgm`.
11. `key_id` لكل حقل مشفّر لتدوير المفاتيح.
12. قيود `EXCLUDE` على: `employments`، `employee_salaries`، `schedule_assignments`، `leave_policy_assignments`، `pay_group_assignments`.

## 5. المحركات

### 5.1 المبدأ المشترك
كل محرك = **نواة نقية** (حساب بلا قاعدة بيانات ولا وقت حالي) + **منسّق** (يحمّل ← يحسب ← يحفظ). فتُختبر بدقة، وتصبح **محاكاة المسيّر** مجرد استدعاء النواة بلا حفظ.

### 5.2 الحضور
```
أحداث خام ← ربط بيوم العمل (نافذة الوردية) ← اقتران الدخول/الخروج (بالسياسة)
← حساب (تأخير، خروج مبكر، ساعات، إضافي) ← حالة اليوم ← attendance_days (upsert)
```
- محفزات إعادة الاحتساب: سجل جديد، تغيير جدول/عطلة/سياسة، موافقة أو إلغاء إجازة، تصحيح معتمد.
- مهمة غير متزامنة idempotent لكل (موظف، تاريخ)، ولا إعادة احتساب لفترة مقفلة.

### 5.3 الإجازات
- الدفتر مصدر الحقيقة. الاستحقاق بمهمة مجدولة وفرادة، المتاح = الرصيد − المعلّق، فحص نهائي تحت قفل عند الموافقة، استهلاك FIFO بحسب الانتهاء، إقفال السنة بمعاينة.

### 5.4 الرواتب
```
تحضير (لقطة الإعدادات والبيانات) ← تقسيم الفترة عند تواريخ التغيير
← لكل موظف: رسم البنود ← ترتيب طوبولوجي ← تقييم المعادلات (Decimal) ← الأسس والشرائح والتقريب
← تحقق وتحذيرات (صافٍ سالب، حساب بنكي ناقص، فرق كبير عن الشهر السابق)
← حفظ payslips + payslip_lines ← مراجعة ← اعتماد (موافقات) ← قفل ← دفع
```
- معاملة لكل موظف داخل مهمة واحدة بدفعات متتالية؛ فشل موظف لا يُسقط المسيّر.
- **مفسّر تعابير مخصص** بقائمة بيضاء ودقة Decimal.
- إعادة الفتح قبل الدفع فقط، وبعده تسوية في الفترة التالية.

### 5.5 الموافقات
- هيكل المسار لقطة عند الإنشاء، والموافقون يُحدَّدون عند تفعيل كل خطوة.
- حالات الطلب: `pending, approved, rejected, returned, cancelled, expired`.
- الأثر على الكيان **متزامن داخل نفس المعاملة**، والآثار الجانبية مهام في الطابور.

### 5.6 التجاوز اليدوي
| الوحدة | التجاوز المتاح |
|---|---|
| الحضور | تعديل نتيجة اليوم (الحالة، الدقائق، الغياب) |
| الإجازات | تعديل عدد أيام الطلب، وحركات تسوية في الدفتر |
| الرواتب | تعديل مبلغ بند، استبعاده، إضافة بند يدوي، **تحويل القسيمة كاملة إلى الوضع اليدوي**، وتسجيل مبلغ مدفوع مختلف |

القواعد: السبب إلزامي، الصفوف اليدوية محمية من إعادة الاحتساب مع تنبيه الفرق، البنود التابعة تُعاد حسابها، العودة للآلي ممكنة، التجاوز حتى قفل الفترة، وتقرير «التجاوزات اليدوية».

## 6. المهام الخلفية والتكاملات

### 6.1 الطابور
- **pg-boss** فوق PostgreSQL مع **إدراج المهمة داخل معاملة العمل**، فالطابور نفسه يقوم بدور Outbox (لا جدول `outbox_events`).
- عملية عمّال منفصلة (`worker.ts`)، وأربع قوائم: `critical`، `default`، `bulk`، `render`.
- جدولة الطابور (قائد واحد) بالمنطقة الزمنية للشركة، وإعادة محاولة بتراجع أسّي، و`job_runs` لما يراه المستخدم.

### 6.2 أجهزة البصمة (المرحلة 2)
- الاستلام: Push حيث يدعمه الجهاز، ووسيط محلي بديلاً (والحسم بعد معرفة الموديلات).
- المسار: `device_raw_logs` ← مطابقة الموظف عبر `employee_external_refs` (النظام `attendance_device`، حسب تاريخ الحدث) ← `attendance_records` ← إعادة احتساب.
- مستخدم غير مربوط، انحراف ساعة، سجل متأخر في فترة مقفلة: تُحجز لقرار HR ولا تُهمل.

### 6.3 الإشعارات والبريد
- القنوات: داخل التطبيق + بريد (MVP)، ثم Push، ثم واتساب، بواجهة `NotificationChannel`.
- مزوّد بريد معاملات خلف `MailTransport` مع SPF/DKIM/DMARC.
- قوالب في القاعدة (حدث × قناة × لغة)، تفضيلات للمستخدم مع فئات إلزامية، وملخص يومي مجمّع للتذكيرات.

### 6.4 الملفات والتوليد
- `StorageProvider`: قرص محلي ثم S3-متوافق، وتشفير بالتطبيق للملفات الحساسة، والتنزيل عبر الـ API برابط موقّع قصير العمر.
- التوليد في قائمة `render`: DOCX (docxtemplater) وHTML→PDF (Playwright) وXLSX (exceljs)، بخطوط عربية مضمَّنة.
- **مدير القوالب:** رفع ← فحص (ماكرو، مطابقة المتغيرات) ← معاينة ← تفعيل ← تراجع. نموذج مستقل لكل لغة.

### 6.5 الاستيراد والتصدير
- دورة: رفع ← تحليل ← تحقق (Dry Run) ← معاينة ← تأكيد ← حفظ على دفعات.
- قوالب ثابتة للبيانات الرئيسية، و`import_profiles` (match_by، الترميز، الفاصل، صيغة التاريخ والمنطقة الزمنية، ربط الأعمدة). غير المطابق أو الملتبس يُحجز لقرار HR.
- **المراجع الخارجية:** `external_systems` (مفتاح، أسماء، `ref_scope`، `is_unique`، تحقق) و`employee_external_refs` (قيمة نصية، فترة صلاحية، `is_primary`، جهاز اختياري). الأكواد نصوص (أصفار بادئة)، وتُطبَّع الأرقام العربية-الهندية ويُكتشف الترميز Windows-1256، وتُمنع التكرارات ببصمة الصف.
- **التصدير (مبسّط):** أي جدول/تقرير يُصدَّر Excel أو CSV (UTF-8 مع BOM) مع أعمدة إضافية من فهرس البيانات (مراجع خارجية، هاتف…). الحساس بصلاحية وتدقيق، والنطاق مُطبَّق، والتخطيط محفوظ في إعدادات المستخدم، والكبير مهمة 202 بملف ينتهي. لا جداول تصدير محاسبية: التصدير للمحاسبة تقرير رواتب عادي + عمود رقم المحاسبة.

## 7. البنية التحتية والنشر

### 7.1 البيئة الأولية
سيرفر Oracle Cloud ARM64 (4 أنوية، 24GB RAM)، النطاق على Cloudflare ومرتبط بالسيرفر بنفق، ويشغّل السيرفر تطبيقات شخصية أخرى بحاويات Docker. **قد تتغير البيئة**، لذلك: الحاويات، والإعدادات الخارجية، و`infra/` في المستودع، وصور متعددة المعمارية.

### 7.2 الحاويات والشبكة
```
Cloudflare ── نفق ──► gateway (Nginx) ─┬─► web (ملفات ثابتة)
                                        └─► /api ► api ──► postgres (داخلية فقط)
                                                   worker ─┘  (+ render)
```
- نفس النطاق للويب والـ API (بلا CORS، وكوكي أبسط وأأمن).
- شبكة Docker خاصة بالمشروع، والبوابة وحدها تنضم لشبكة النفق، وPostgreSQL غير مكشوف.
- الأدوات الإدارية خلف Cloudflare Access.
- `trust proxy` وقراءة `CF-Connecting-IP`، ومراعاة حد حجم الرفع (نحو 100MB حسب الخطة).

### 7.3 تقدير الموارد (تقديري، يُقاس عند التشغيل)

| الخدمة | الذاكرة (حد) |
|---|---|
| PostgreSQL | ~3–4GB |
| api | ~1GB |
| worker | ~1GB |
| render | ~1.5–2GB (تزامن 1–2) |
| gateway | ~128MB |
| **الأقصى** | **~8GB** (يبقى ~16GB لبقية التطبيقات) |

حدود `mem_limit` و`cpus` لكل حاوية كي لا يتأثر المشروع ولا التطبيقات الأخرى.

### 7.4 البيئات والنشر
- بيئات: تطوير محلي، **Staging على نفس السيرفر** (خلف Cloudflare Access)، إنتاج.
- **GitHub Actions:** اختبارات وأنواع وlint وفحص ثغرات (Trivy) وتحديثات تبعيات آلية، ثم بناء صور (arm64 + amd64) ودفعها إلى سجل، والنشر بسكربت SSH: سحب الصور ← تهجير القاعدة (مستقل) ← إعادة تشغيل بفحوص الجاهزية.
- **Expand → Contract** للتهجيرات فلا ينكسر شيء أثناء النشر ويمكن التراجع.

### 7.5 النسخ الاحتياطي
| ما | كيف |
|---|---|
| القاعدة | نسخة منطقية ليلية + أرشفة WAL مستمرة (استعادة لنقطة زمنية) |
| الملفات | نسخ تزايدي مشفّر |
| المكان | **خارج السيرفر دائماً** (+ نسخة محلية كطبقة إضافية) |
| الاحتفاظ | يومي 14 + أسبوعي 8 + شهري 12 (قابل للضبط) |
| الأهداف المقترحة | فقد بيانات ≤ 15 دقيقة، واستعادة ≤ 4 ساعات |
| التحقق | **استعادة آلية شهرية إلى Staging** مع فحص سلامة |
| المفاتيح | مفتاح تشفير الحقول والملفات **منفصل عن النسخ**، وله إجراء استرجاع موثّق (**فقدانه = فقدان المشفّر نهائياً**) |

### 7.6 المراقبة والأمان
- مراقبة خفيفة: `/health/live` و`/health/ready`، مراقب توفر خارجي، تتبع أخطاء (Sentry أو GlitchTip)، تدوير سجلات، تنبيه عند فشل المهام أو النسخ أو امتلاء القرص.
- الأسرار: ملفات بيئة بصلاحيات مقيّدة تُحقن من أسرار CI.
- الحاويات: غير root، قراءة فقط حيث أمكن، بلا منافذ مكشوفة.
- Cloudflare: WAF وحماية روبوتات وتحديد معدّل إضافي على `/auth/*`.
- السيرفر: تحديثات أمنية تلقائية، SSH بالمفاتيح، جدار ناري.

## 8. مثال متكامل: دورة طلب إجازة

1. الموظف: `POST /me/leave-requests` ← مسودة، وتُحسب الأيام بحسب جدوله والعطل.
2. `POST /leave-requests/:id/submit` ← يُنشأ طلب موافقة، ويُحدَّد موافق الخطوة الأولى (المدير) ويُسجَّل في `approval_request_assignees`، وتُرسل إشعاراً.
3. المدير: `GET /approvals/inbox` ثم `POST /approvals/:id/actions { action: "approve" }`.
4. عند آخر موافقة، **في نفس المعاملة:** تُحدَّث حالة الطلب، ويُفحص الرصيد تحت قفل، وتُكتب حركة استهلاك في `leave_ledger`.
5. **مهام في الطابور (من نفس المعاملة):** إعادة احتساب أيام الحضور المتأثرة (وسمها «إجازة»)، وإشعار الموظف.
6. إلغاء بعد الموافقة: `POST /leave-requests/:id/cancel` ← حركة عكس في الدفتر ← إعادة احتساب الحضور.
7. كل خطوة مسجّلة في `audit_logs`.

## 9. البدائل المستبعدة ولماذا

| البديل | سبب الاستبعاد |
|---|---|
| Microservices / Kubernetes | سيرفر واحد وفريق صغير؛ التعقيد بلا فائدة. Modular Monolith بحدود صارمة يكفي ويسهّل الفصل لاحقاً |
| Prisma كـ ORM | القيود المتقدمة (`EXCLUDE`، الفهارس الجزئية، RLS، `FOR UPDATE`) لا تُعبَّر عنها جيداً، وتصميمنا قاعدة أولاً |
| Redis/BullMQ للطابور | مكوّن إضافي، والطابور فوق PostgreSQL يدعم الإدراج داخل المعاملة ويكفي |
| جدول `outbox_events` | الطابور الذي يدعم الإدراج داخل المعاملة يغني عنه |
| `expr-eval` وأمثاله للمعادلات | تحسب بأعداد عائمة (float) وتخالف قرار الدقة |
| `eval` أو تنفيذ تعابير حرة | خطر أمني |
| تعديل القيم المحسوبة مباشرة | تفقد الأصل وتتعارض مع إعادة الاحتساب، فاعتمدنا الأعلام + لقطة آلية |
| صلاحيات داخل التوكن | تبقى صلاحية ملغاة نافذة حتى انتهاء التوكن |
| تخزين التوكن في localStorage | عرضة للسرقة بـ XSS |
| `api.` نطاق فرعي مستقل | يفرض CORS ويعقّد كوكي الـ Refresh |
| مسارات موافقة لكل كيان | تشتّت التفويض والتصعيد والتدقيق؛ اعتمدنا نقطة موحّدة |
| مصمم تقارير ونماذج مرئي داخل الـ MVP | ميزة كبيرة؛ تأجّلت لمشروع مستقل مع الإبقاء على فهرس البيانات و`manifest` |
| ENUM في القاعدة | تعديله يتطلب Migration، والقوائم لدينا قابلة للضبط |
| الأرصدة كأرقام مجمّعة فقط | بلا تفسير ولا تدقيق؛ اعتمدنا دفتر الحركات |

## 10. الواجهة الأمامية

### 10.1 الأساس
Vite SPA مع TanStack Router (معاملات بحث بأنواع، مسارات lazy، حراس مسارات). مخططات Zod مشتركة من `packages/shared`، وإعداد وقت التشغيل من `/config.json`. تحديث التوكن بمسار واحد مع تسجيل خروج متزامن بين التبويبات. Mantine + TanStack Table + React Hook Form بعد spike قصير (البديل Ant Design). خصائص CSS منطقية فقط، وخطوط عربية ذاتية الاستضافة، وi18next. الأرقام والتواريخ من الإعدادات، والمال نص عشري، والعرض الهجري عبر `Intl` أولاً.

### 10.2 الحالة والنماذج والصلاحيات
- TanStack Query (+Zustand لحالة الواجهة فقط)، الفلاتر في الـ URL، `Idempotency-Key` لكل محاولة إرسال، و`VERSION_CONFLICT` يحافظ على مدخلات المستخدم.
- `DynamicForm` واحد مبني من تعريفات الحقول مع `buildZodFromFields` المشترك؛ حقول حساسة مقنّعة مع «إظهار» مدقَّق؛ حارس تغييرات غير محفوظة؛ التغييرات المؤرَّخة كخط زمني.
- الصلاحيات عبر `usePermission` وكائن `can`، وإخفاء مقابل تعطيل بسبب، و`X-Permissions-Version`. خروج بعد 30 دقيقة خمول، وإعادة مصادقة (step-up) لاعتماد/قفل/إعادة فتح الرواتب والتصدير الحساس وإظهار الحقول الحساسة.

### 10.3 الجداول والتصدير
ترقيم وترتيب وفلترة من الخادم بحالة في الـ URL، وvirtualization لجداول الـ cursor، وتعريفات فلاتر مشتركة، وتخصيص الأعمدة محفوظ للمستخدم، وتحديد جماعي (الصفحة أو كل نتائج الفلتر)، وإجماليات من `meta.summary`. شبكة خفيفة قابلة للتعديل مع لصق من Excel للحضور ومدخلات الرواتب ومعاينة الاستيراد. التصدير بمنتقي «أعمدة إضافية» (قسم 6.5).

### 10.4 الشاشات الرئيسية
قائمة جانبية من الصلاحيات، بحث عام يشمل المراجع الخارجية، إشعارات ومبدّل نطاق · لوحات حسب الدور · بطاقة موظف بتبويبات (بيانات، وظيفة، رواتب، إجازات، حضور، أرشيف، مراجع خارجية) · شجرة الهيكل · الحضور (لوحة يومية، تقويم، شبكة يدوية، معالج استيراد، تصحيحات) · الإجازات (تقويم الفريق، نموذج برصيد حي عبر `leave-requests/preview`) · صندوق موافقات موحد · الرواتب كمعالج خطوات (ملخص، تفصيل القسيمة، «كيف حُسب؟»، شارة يدوي، محاكاة، مقارنة بالشهر السابق، step-up) · مدير القوالب · مركز التقارير · الإعدادات (أنواع الوثائق، الأنظمة الخارجية، ملفات الاستيراد، مصفوفة الأدوار، التدقيق، مراقب المهام، التنسيقات) · `/me` للخدمة الذاتية بتخطيط يناسب الموبايل.

### 10.5 الأدوات والاختبار والنشر
ESLint + `jsx-a11y` + Prettier + stylelint، وعميل API مُولَّد من OpenAPI، وTabler Icons وMantine Charts. اختبارات: Vitest + Testing Library + MSW، وPlaywright للمسارات الحرجة (RTL وaxe). ميزانية حجم الحزمة، GlitchTip ذاتي مع إخفاء الحقول الحساسة، إشعار «إصدار جديد» دون فرض إعادة تحميل، تقديم من Nginx مع brotli.

### 10.6 الموبايل (لاحقاً)
PWA للخدمة الذاتية أولاً، ثم Expo (React Native) للحضور (GPS + QR) بمشاركة `packages/shared`. متطلبات الخادم: توكن بـ `Authorization`، ربط `device_id` بالجلسة، QR ديناميكي HMAC قصير العمر مع تحقق الموقع في الخادم.
