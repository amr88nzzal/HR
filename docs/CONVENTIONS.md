## 1. مبادئ عامة

- **المعرّفات والتعليقات في الكود بالإنجليزية**، والواجهة والوثائق بالعربية عبر نظام ترجمة (i18n).
- **القواعد بيانات قابلة للضبط وليست منطقاً مكتوباً في الكود** (الإجازات، الرواتب، الورديات، القوانين).
- **API-first:** الويب والموبايل يستهلكان نفس الـ API.
- **كل نتيجة محسوبة قابلة للتجاوز اليدوي الموثّق** (انظر القسم 12).
- **قابلية النقل:** كل شيء في حاويات، والإعدادات بمتغيرات بيئة، ولا اعتماد على خدمة مزوّد بعينه إلا خلف واجهة قابلة للاستبدال.
- **الاتساق أهم من التفضيل الشخصي:** ما يُفرض آلياً (ESLint / Prettier / TypeScript strict) يُفضَّل على ما يُترك للانضباط اليدوي.

## 4. التسمية

### 4.1 التحويل بين القاعدة والكود
- **القاعدة:** `snake_case`.
- **الكود والـ API:** `camelCase`.
- **التحويل تلقائي في طبقة البيانات (Repository)** في مكان واحد، ولا يُكتب يدوياً في الاستعلامات.

### 4.2 جدول القواعد

| المنطقة | القاعدة | مثال |
|---|---|---|
| جداول القاعدة | جمع، `snake_case` | `employees`, `leave_requests` |
| أعمدة القاعدة | `snake_case` | `first_name` |
| المفتاح الأساسي | `id` | |
| المفتاح الأجنبي | `<مفرد>_id` | `employee_id` |
| منطقي (قاعدة) | `is_` / `has_` | `is_active` |
| وقت | `_at` | `created_at` |
| تاريخ | `_date` | `hire_date` |
| فهرس / فرادة / أجنبي / تحقق | `idx_` / `uq_` / `fk_` / `ck_` | `idx_employments_employee_id` |
| متغيرات ودوال | `camelCase` | `userName`, `getEmployeeById` |
| أصناف وأنواع ومكونات React | `PascalCase` | `EmployeeForm`, `LeaveRequest` |
| ثوابت | `UPPER_SNAKE_CASE` | `MAX_RETRIES` |
| منطقي (كود) | `is` / `has` / `can` | `isActive`, `canApprove` |
| مسارات الـ API | `kebab-case` بالجمع | `/api/v1/employees/:id/leave-requests` |
| حقول JSON ومعاملات الاستعلام | `camelCase` | `firstName` |
| قيم الحالات | نصوص `snake_case` صغيرة | `pending_approval` |
| رموز الأخطاء | `UPPER_SNAKE_CASE` | `EMPLOYEE_NOT_FOUND` |
| مفاتيح الترجمة | نقاط + `camelCase` | `employees.fields.fullName` |
| الصلاحيات | `module.resource.action` | `payroll.run.approve` |

### 4.3 أسماء الملفات
- **الباك إند:** `kebab-case` مع لاحقة الدور: `employee.service.ts`.
- **مكونات React:** `PascalCase`: `EmployeeForm.tsx`.
- **المجلدات:** `kebab-case`.

## 5. المعرّفات (IDs)

- **UUIDv7** لكل المفاتيح الأساسية (مرتّب زمنياً فيحسّن أداء الفهارس، وغير قابل للتخمين).
- أرقام الموظفين والوثائق والتسلسلات المقروءة **حقول مستقلة** وليست المعرّف.

## 6. كتابة الدوال

- **Arrow functions مع `const` في كل مكان.**
- **تصدير مسمّى** (`export const ...`) ولا `export default`.
- **عدم الاعتماد على `this`** داخل الدوال.
- **استثناءات `function` المقبولة فقط:** التحميل الزائد (overloads)، المولّدات `function*`، أو حاجة فعلية للرفع (hoisting). وتُفرض القاعدة بـ ESLint.
- **غرض واحد لكل دالة.**
- **كائن معاملات** عند وجود أكثر من معاملين.
- **`async/await` فقط**، دون callbacks متداخلة.
- **دوال نقية** لمنطق الحسابات (محرك الرواتب، استحقاق الإجازات، احتساب الحضور) بلا وصول للقاعدة ولا للوقت الحالي (الوقت يُمرَّر كمعامل).

```ts
export const createLeaveRequest = async (
  ctx: Ctx,
  { employeeId, leaveTypeId, from, to, reason, isHalfDay }: CreateLeaveRequestParams,
) => {
  // ...
};

export const calculateDailyRate = ({ monthlySalary, dayBasis, daysInMonth }: Params) =>
  monthlySalary.div(dayBasis === 'fixed_30' ? 30 : daysInMonth);
```

## 7. الطبقات والسياق (`ctx`) وحدود الوحدات

### 7.1 ثلاث طبقات
| الطبقة | المسؤولية |
|---|---|
| **Controller** | HTTP فقط: قراءة الطلب، التحقق (Zod)، استدعاء الخدمة، تشكيل الاستجابة |
| **Service** | قواعد العمل والمعاملات |
| **Repository** | SQL والتحويل بين `snake_case` و`camelCase`، وتطبيق `applyScope` |

### 7.2 نمط `ctx`
كل دالة خدمة تأخذ `ctx` كأول معامل:

```ts
type Ctx = {
  db: Db | Tx;                         // اتصال أو معاملة
  user: { id: string; employeeId: string | null };
  companyId: string;
  scopes: ScopeSet;                    // نطاقات الصلاحيات المحمّلة
  requestId: string;
  locale: 'ar' | 'en';
};
```

بهذا: **معاملة واحدة لكل عملية عمل**، و**فرض `company_id` ونطاق الصلاحيات تلقائياً في كل استعلام**، وسهولة الاختبار بتمرير `ctx` تجريبي.

### 7.3 المعاملات
- معاملة صريحة لعمليات الكتابة فقط: `runInTransaction(ctx, fn)`. القراءة بلا معاملة.

### 7.4 حدود الوحدات (طبقات صارمة)

| الطبقة | الوحدات |
|---|---|
| أساسية (لا تعتمد على أحد) | `system`, `identity`, `org` |
| بيانات الأعمال | `employees` |
| تشغيلية | `archive`, `attendance`, `leaves`, `approvals` |
| قمة (تقرأ من الجميع) | `payroll`, `letters`, `reports` |

- الاعتماد **من الأعلى إلى الأسفل فقط**، وعبر `index.ts` للوحدة، **ولا حلقات**، ويُمنع الوصول لمستودع وحدة أخرى.
- تُفرض بـ `eslint-plugin-boundaries`، والعكس (من الأسفل للأعلى) يتم **بالأحداث**.

### 7.5 الأحداث الداخلية
- **الآثار الحرجة** (حالة الكيان + حركات الدفتر): معالج **متزامن داخل نفس المعاملة**.
- **الآثار الجانبية** (إعادة احتساب الحضور، الإشعارات، البريد): **مهام تُدرَج في الطابور داخل نفس المعاملة** (الطابور نفسه يقوم بدور Outbox، فلا يضيع حدث)، وتُنفَّذ بإعادة محاولة.

## 8. التحقق والأخطاء

- **التحقق: Zod** كـ Middleware للمسار والاستعلام والجسم، والمخططات المشتركة في `packages/shared`، وتُولَّد من تعريفات الحقول الديناميكية عند الحاجة (مع تخزين مؤقت بحسب إصدار التعريف).
- **الأخطاء:** استثناءات مُنمَّطة (`AppError`) برموز ثابتة، ومعالج مركزي واحد. الرسائل مفاتيح ترجمة.
- **شكل الخطأ:**
```json
{ "error": { "code": "EMPLOYEE_NOT_FOUND", "status": 404, "message": "...", "details": [], "requestId": "..." } }
```
- `code` ثابت للمنطق في الواجهة، و`message` مترجمة، و`details` أخطاء الحقول.
- **404** لسجل خارج نطاق المستخدم (لعدم كشف وجوده)، و**403** عند غياب الصلاحية على الإجراء نفسه.
- **`VERSION_CONFLICT`** عند تعارض القفل المتفائل.

## 9. المال والتواريخ

### المال
- القاعدة: `numeric(18,4)`، وكل مبلغ يقترن دائماً بعمود `currency`.
- الكود: **`decimal.js`**، ولا `number` للمبالغ أبداً.
- الـ API: **نص عشري** (`"1500.0000"`).
- التقريب عند نقاط محددة وبطريقة قابلة للضبط (افتراضياً على كل بند، والصافي = مجموع البنود المقرَّبة).
- طريقة العرض (خانات عشرية، فواصل، رمز العملة) من الإعدادات، والـ API يُرجع القيم الخام.
- **العملات المتعددة:** حالة استثنائية، عملة لكل سجل راتب، ومسيّر لكل عملة، وأسعار الصرف للتقارير فقط، وميزة قابلة للتعطيل (`multi_currency_enabled`).

### التواريخ
- الأحداث: `timestamptz` بتوقيت UTC.
- التواريخ التقويمية (ميلاد، تعيين): نوع `date` بلا منطقة زمنية.
- صيغة العرض ونوع التقويم (ميلادي/هجري) من الإعدادات.
- `work_date` في الحضور يُحسب بالمنطقة الزمنية للموظف.

## 10. قاعدة البيانات

- **`company_id` في كل جدول يخص بيانات الشركة** (جاهزية SaaS وRow-Level Security)، مع مفاتيح أجنبية مركّبة حيث أمكن.
- **الأعمدة المشتركة:** `created_at`, `updated_at`, `created_by`, `updated_by`, `deleted_at`.
- **القفل المتفائل:** عمود `version` (integer) في الجداول القابلة للتعديل.
- **حذف ناعم:** قيود الفرادة فهارس جزئية `WHERE deleted_at IS NULL`.
- **الامتداد الزمني:** `valid_from / valid_to` مع `EXCLUDE USING gist` (امتداد `btree_gist`) لمنع تداخل الفترات في: `employments`، `employee_salaries`، `schedule_assignments`، `leave_policy_assignments`، `pay_group_assignments`.
- **قوائم قابلة للتعديل:** جداول مرجعية بدل `ENUM`.
- **قواعد مرنة:** أعمدة `jsonb`.
- **البحث بالعربية:** عمود `search_text` مُطبَّع (توحيد الألف والياء والتاء المربوطة، حذف التشكيل) مع `pg_trgm`.
- **التشفير:** الحقول الحساسة مشفّرة على مستوى التطبيق (AES-256-GCM) مع `key_id` لتدوير المفاتيح، وبصمة مجزَّأة (Blind Index) للبحث.
- **أعمدة التجاوز اليدوي** على صفوف النتائج: `calc_mode`، `manual_reason_id`، `manual_note`، `overridden_by`، `overridden_at`، `auto_snapshot`.
- **التهجيرات:** ملفات SQL متتابعة **لا تُعدَّل بعد تطبيقها**، الاسم: `YYYYMMDDHHMM_description`، وبأسلوب **Expand → Contract** (تغييرات متوافقة مع النسختين القديمة والجديدة).
- **الأعمدة المضافة بعد المراجعة:** `refresh_tokens.family_id` و`replaced_by_id`، `leave_ledger.idempotency_key` (فريد)، `attendance_days.inputs_hash`، `payroll_runs.config_snapshot`، `payslips.warnings`.

## 11. الـ API

- النسخ في المسار: **`/api/v1`**، والتوثيق OpenAPI.
- **أسلوب الاستجابة:** غلاف دائماً: `{ data }` و`meta` للصفحات.
- **REST مع مسارات أفعال** لتغيّرات الحالة (`POST /payroll-runs/:id/lock`)، و**PATCH جزئي** للتعديل مع `version`.
- **الموافقات:** نقطة موحّدة `POST /approvals/:id/actions`؛ ومسارات الكيان لأفعال مقدّم الطلب فقط (إرسال، إلغاء).
- **التصفية:** معاملات بسيطة بقائمة بيضاء لكل مورد: `?status=active&branchId=…&sort=-createdAt&q=أحمد&page=1&pageSize=25`.
- **ترقيم الصفحات:** Offset (الافتراضي 25، الأقصى 100) للجداول الإدارية، وCursor للجداول الضخمة (الحضور، التدقيق). **العدّ الكلي عند الطلب فقط** (`?withTotal=true`).
- **العمليات الطويلة:** `202 Accepted` + `jobId`، والمتابعة بـ `GET /jobs/:id`.
- **الإشعارات:** استعلام دوري في الـ MVP (`/notifications/unread-count`) ثم SSE.
- **الخدمة الذاتية:** `/me/*` (تستدعي نفس الخدمات بنطاق «ذاتي»).
- **العمليات الجماعية:** مسارات `bulk` مستقلة بنتيجة لكل صف؛ والكبيرة عبر `imports`.
- **الحقول المحجوبة:** تُحذف من الاستجابة عند غياب الصلاحية، مع كائن `can` (`{ edit, delete, viewSalary }`) في المورد، عبر مُسلسِل (Serializer) لكل مورد.
- **الحقول الديناميكية:** كائن `values` بمفاتيح الحقول.
- **البيانات المرجعية:** `nameAr` و`nameEn` + `displayName` محلولة حسب اللغة.
- **العمليات الحرجة** (تشغيل المسيّر، الدفع، الاستيراد): ترويسة `Idempotency-Key`.
- **التاريخ:** ISO 8601، **والمبالغ:** نصوص عشرية، **والمعرّفات:** UUID نصية.

## 12. المحركات (الحضور، الإجازات، الرواتب، الموافقات)

### 12.1 البنية
كل محرك = **نواة نقية** (دوال حساب) + **منسّق** (يحمّل المدخلات ← يستدعي النواة ← يحفظ). اختبارات **ملفات سيناريو** (مدخلات JSON ← نتيجة متوقعة)، واختبار خصائص للتقريب (مجموع البنود = الصافي دائماً).

### 12.2 مفسّر التعابير (موحَّد)
- **مفسّر مخصص فوق محلّل (مثل jsep)** يقيّم AST بقائمة بيضاء من الدوال (`min, max, round, if, abs`) وبـ **decimal.js**.
- **ممنوع `eval`** والمكتبات التي تحسب بأعداد عائمة (float).
- يخدم معادلات الرواتب وشروط مسارات الموافقة.
- ترتيب طوبولوجي للبنود مع **كشف الحلقات عند حفظ المعادلة**.

### 12.3 الحضور
- ربط الأحداث بيوم العمل **بنافذة الوردية**؛ الاقتران (أول/آخر أو تسلسلي) يُضبط بالسياسة؛ **تبديل تلقائي** للأحداث بلا اتجاه.
- الاحتساب **مهمة غير متزامنة idempotent لكل (موظف، تاريخ)** مع debounce، و`inputs_hash` لتخطي ما لم يتغير.
- **لا بصمات في يوم عمل = غياب**، و**بصمة واحدة = `incomplete`** مع تنبيه للتصحيح قبل الإقفال.
- لا إعادة احتساب لفترة مقفلة.

### 12.4 الإجازات
- **دفتر حركات (`leave_ledger`)** هو مصدر الحقيقة؛ الرصيد المخزَّن نسخة تُعاد بناؤها منه.
- الاستحقاق: **مهمة مجدولة تكتب حركات** بمفتاح فرادة (موظف، نوع، سياسة، فترة)، وتشغيل تعويضي عند الإسناد بأثر رجعي.
- **المتاح = الرصيد − الطلبات المعلّقة**، مع فحص نهائي تحت **قفل صف** عند الموافقة.
- الاستهلاك **FIFO حسب تاريخ الانتهاء** (دالة نقية `allocateUsage`).
- إقفال السنة: مهمة مجدولة مع **تقرير معاينة** قبل التنفيذ.
- عدد أيام الطلب يُحسب عند الحفظ ويُحفظ، بحسب جدول الموظف والعطل.

### 12.5 الرواتب
- المسار: تحضير (لقطة `config_snapshot`) ← تقسيم الفترة عند تواريخ التغيير ← حساب كل موظف ← تحقق وتحذيرات ← حفظ.
- **التقريب على كل بند**، والصافي = مجموع البنود المقرَّبة (قابل للتغيير بمجموعة الدفع).
- **معاملة لكل موظف** داخل مهمة واحدة بدفعات متتالية؛ فشل موظف لا يُسقط المسيّر؛ والتنفيذ idempotent قبل القفل.
- إعادة الحساب للمسيّر كله أو لموظف منفرد قبل القفل.
- **اعتماد المسيّر عبر محرك الموافقات.**
- **إعادة الفتح قبل الدفع فقط** بصلاحية وسبب وموافقة؛ وبعد الدفع تُصحَّح بمدخلات تسوية في الفترة التالية.
- أقساط السلف: مدخلات تلقائية عند فتح المسيّر، وتُعلَّم «خُصمت» عند القفل.
- **القسيمة قالب في مدير القوالب**، وتُولَّد عند الطلب ويُخزَّن الملف.

### 12.6 الموافقات
- هيكل المسار يُحفظ **لقطة عند الإنشاء**، **والموافقون يُحدَّدون عند تفعيل كل خطوة**، ويُسجَّل من حُدِّد فعلياً.
- تخطٍّ تلقائي إن كان الموافِق هو المقدّم أو غير نشط، موافق **بديل** إلزامي، **تصعيد مجدول** بعد مهلة، والتفويض يُطبَّق عند تفعيل الخطوة.
- `approval_request_assignees` لصندوق «موافقاتي».
- منع الحلقات في التسلسل الإداري.

### 12.7 التجاوز اليدوي (Manual Override)
- **أعلام على صف النتيجة + لقطة للقيمة الآلية (`auto_snapshot`) + سجل التدقيق** (بدل جدول عام).
- **الصفوف اليدوية محمية من إعادة الاحتساب** مع تنبيه «المدخلات تغيّرت بعد التعديل اليدوي» وعرض الفرق، والخيار بين **العودة للآلي** و**إبقاء اليدوي**.
- تعديل بند يُعيد حساب **البنود التابعة** تلقائياً، ويمكن تجاوز أي منها.
- **السبب إلزامي** من قائمة قابلة للضبط (`override_reasons`) + ملاحظة.
- **الموافقة حسب شرط قابل للضبط** (افتراضياً فوري لـ HR مع سبب وتدقيق، وبموافقة عند تجاوز حد أو في مرحلة المراجعة فأعلى).
- **صلاحية مستقلة لكل وحدة:** `attendance.day.override`، `leaves.balance.adjust`، `payroll.payslip.override`.
- التجاوز **حتى قفل الفترة**، وبعدها عبر إعادة الفتح الموثّقة أو تسوية في الفترة التالية.
- شارة «يدوي» على كل صف، وتقرير **«التجاوزات اليدوية»**، وإبرازها في شاشة اعتماد المسيّر.

## 13. المهام الخلفية

- **pg-boss** فوق PostgreSQL، مع **إدراج المهمة داخل معاملة العمل**.
- **عملية عمّال منفصلة** (`worker.ts`) من نفس الصورة.
- **أربع قوائم:** `critical` (الرواتب والموافقات)، `default`، `bulk` (استيراد/تصدير)، `render` (PDF بتزامن 1–2).
- **جدولة الطابور نفسه** (قائد واحد) بالمنطقة الزمنية للشركة.
- **إعادة محاولة بتراجع أسّي + مفتاح فرادة (idempotency)**، وكل المهام تتحمل التكرار.
- **`job_runs`** للمهام التي يراها المستخدم (تقدّم، أخطاء لكل صف، نتيجة)، ولوحة إدارية للفاشلة مع إعادة محاولة وتنبيه عند تكرار الفشل.

| المهمة المجدولة | التكرار |
|---|---|
| توليد تذكيرات الوثائق وتنبيهات انتهاء العقود | يومياً |
| استحقاق الإجازات | أول كل شهر (وتعويضي عند الحاجة) |
| ترحيل/انتهاء الإجازات | نهاية فترة الاستحقاق |
| تصعيد الموافقات المتأخرة | كل ساعة |
| إعادة احتساب الحضور المتراكم | مستمرة (مجمّعة) |
| تنظيف التوكنات المنتهية والملفات المؤقتة | يومياً |

## 14. الأمان

- **المصادقة:** JWT قصير العمر (~15 دقيقة) + **Refresh Token دوّار** مع `family_id` (استخدام توكن قديم يُلغي الفرع كله)، ويُخزَّن مُجزَّأً.
- **الويب:** Access Token في الذاكرة + Refresh في **كوكي httpOnly**؛ **الموبايل:** التخزين الآمن للجهاز.
- **محتوى التوكن:** هوية فقط (`userId`, `companyId`, `sessionId`)؛ الصلاحيات من **ذاكرة مؤقتة قصيرة** تُبطَل عند تغيير الأدوار.
- **الصلاحيات:** RBAC بنطاق (شركة / فرع / قسم / فريق / ذاتي)، وفحصها بـ `requirePermission('module.resource.action')`، وصلاحية مستقلة للحقول الحساسة (مثل `employees.salary.read`).
- **فرض النطاق:** دالة مشتركة `applyScope` في المستودع + **RLS على `company_id`** كطبقة إضافية.
- **التدقيق (هجين):** Triggers تلتقط قبل/بعد مع هوية المنفّذ عبر `SET LOCAL`، واستدعاءات صريحة للأحداث العملية (دخول، موافقة، تصدير، **قراءة بيانات حساسة**). السجل للإضافة فقط، بتقسيم شهري.
- **رفع الملفات:** تحقق من النوع الحقيقي (Magic Bytes) والحجم والامتداد؛ **ClamAV لاحقاً**.
- **تحديد المعدّل:** عام + **صارم** للدخول واستعادة كلمة المرور (حسب الحساب والعنوان معاً).
- **IP الحقيقي:** `trust proxy` وقراءة `CF-Connecting-IP`.
- **التشفير:** الحقول الحساسة والملفات المعلَّمة حساسة مشفّرة بالتطبيق (مع `key_id`)، **ومفتاح التشفير يُحفظ منفصلاً عن النسخ الاحتياطية** وله إجراء استرجاع موثّق.
- **لا بيانات حساسة في السجلات.**

## 15. الملفات والتوليد والتكاملات

- **التخزين:** واجهة `StorageProvider`؛ البدء بقرص محلي، والتحويل إلى S3-متوافق بالإعداد. **التنزيل عبر الـ API** بصلاحية وتدقيق ورابط موقّع قصير العمر. للمؤقت `expires_at`.
- **القوالب:** يرفعها HR من «مدير القوالب» (docx / html / xlsx): رفع ← فحص (رفض الماكرو، مطابقة المتغيرات مع الفهرس) ← معاينة ← تفعيل (`templates.activate`) ← تراجع. **نموذج مستقل لكل لغة.** كل وثيقة صادرة تحتفظ بـ PDF ثابت ورقم إصدار القالب وبصمته (`file_hash`).
- **فهرس البيانات:** يُعرَّف في الكود ويُزامَن للقاعدة؛ المتغيرات بمفاتيح ثابتة `{{employee.full_name}}` ودليل متغيرات بأسماء عربية.
- **التقارير الجاهزة:** `reports/<code>/` فيه `manifest.json` + الاستعلام + قالب الإخراج، وتمر عبر طبقة مشتركة تطبّق النطاق وحجب الحقول الحساسة. مصمم التقارير **مشروع مستقل** لاحقاً ينتج نفس الـ manifest.
- **التوليد:** حاوية `render` بخطوط عربية مضمَّنة في الصورة، و**Prototype مبكر على ARM64** (DOCX→PDF وHTML→PDF) قبل اعتماد الصيغة الأساسية. تُرفض الملفات ذات الماكرو.
- **الإشعارات:** MVP: داخل التطبيق + بريد (مزوّد بريد معاملات خلف واجهة `MailTransport`، مع SPF/DKIM/DMARC)، ثم Push مع الموبايل، ثم واتساب لاحقاً، بواجهة `NotificationChannel`. قوالب في القاعدة لكل (حدث، قناة، لغة)، تفضيلات للمستخدم مع فئات إلزامية، ملخص يومي مجمّع للتذكيرات، ومهمة لكل تسليم.
- **أجهزة البصمة (المرحلة 2):** Push حيث يدعمه الجهاز، ووسيط محلي بديلاً (والحسم بعد معرفة الموديلات). مسار: `device_raw_logs` ← مطابقة الموظف عبر `employee_external_refs` (النظام الخارجي `attendance_device`، حسب تاريخ الحدث) ← `attendance_records` ← إعادة احتساب. المستخدمون غير المربوطين والسجلات المتأخرة في فترة مقفلة تُحجز لقرار HR، وانحراف ساعة الجهاز يُنبَّه عليه.
- **الاستيراد:** رفع ← تحليل ← تحقق (Dry Run) ← معاينة بتقرير أخطاء ← تأكيد ← حفظ على دفعات idempotent. قوالب ثابتة للبيانات الرئيسية، و`import_profiles` (match_by + ترميز + فاصل + صيغة تاريخ + ربط أعمدة) لاستيراد الحضور وغيره. الصفوف غير المطابقة أو الملتبسة تُحجز لقرار HR، وتُمنع البصمة المكررة ببصمة الصف (`external_ref`).
- **المراجع الخارجية:** `external_systems` (مفتاح، أسماء، `ref_scope`، `is_unique`، تحقق) + `employee_external_refs` (قيمة **نصية** بأصفار بادئة محفوظة، فترة صلاحية، `is_primary`، جهاز اختياري). تُطبَّع الأرقام العربية-الهندية، ويُكتشف الترميز (Windows-1256).
- **التصدير:** أي تقرير/جدول يُصدَّر إلى Excel (exceljs) أو CSV (UTF-8 مع BOM وفاصل قابل للاختيار) مع **أعمدة إضافية** تُختار من فهرس البيانات (مثل `employee.external.accounting`, `employee.phone`). الحقول الحساسة بصلاحية وتدقيق، والنطاق مُطبَّق. الأكواد نصوص، والمبالغ أرقام في XLSX ونصوص عشرية في CSV. الصغير تحميل مباشر والكبير مهمة 202. تخطيط الأعمدة محفوظ في `settings` المستخدم. **لا ملفات تعريف تصدير محاسبية** (التصدير للمحاسبة = تقرير عادي + عمود رقم المحاسبة).

## 16. البنية والنشر

- **Docker Compose**؛ الخدمات: `postgres` (حاوية PostgreSQL 18 مستقلة)، `api`، `worker` (+`render`)، `gateway` (Nginx: يخدم ملفات الويب ويوجّه `/api`).
- **نفس النطاق (Same-origin)** للويب والـ API، وبوابة واحدة تستقبل النفق من Cloudflare.
- **شبكة Docker خاصة بالمشروع**، والبوابة وحدها تنضم لشبكة النفق، وPostgreSQL لا يُكشف على منافذ السيرفر.
- **الأدوات الإدارية** خلف Cloudflare Access.
- **حدود موارد** (`mem_limit`, `cpus`) لكل حاوية، ومستخدم غير root، ونظام ملفات للقراءة فقط حيث أمكن.
- **صور متعددة المعمارية (arm64 + amd64)**.
- **البيئات:** تطوير محلي، **Staging على نفس السيرفر** (موارد أقل، خلف Cloudflare Access)، إنتاج.
- **CI/CD (GitHub Actions):** اختبارات + أنواع + lint + فحص ثغرات الحزم والصور (مثل Trivy) + تحديثات تبعيات آلية؛ بناء الصور ودفعها إلى سجل صور؛ **نشر بسكربت عبر SSH:** سحب الصور ← تهجير القاعدة (خطوة مستقلة) ← إعادة تشغيل مع فحوص الجاهزية.
- **الأسرار:** ملفات بيئة على السيرفر بصلاحيات مقيّدة تُحقن من أسرار CI، ولا أسرار في Git.
- **النسخ الاحتياطي:** نسخة منطقية ليلية + أرشفة WAL مستمرة (استعادة لنقطة زمنية)، ونسخ تزايدي مشفّر لمجلد الملفات، **خارج السيرفر دائماً**. الاحتفاظ: يومي 14 + أسبوعي 8 + شهري 12. **هدف مقترح:** فقد بيانات ≤ 15 دقيقة، واستعادة ≤ 4 ساعات. **استعادة آلية شهرية إلى Staging** مع فحص سلامة.
- **المراقبة (خفيفة):** `/health/live` و`/health/ready`، مراقب توفر خارجي، تتبع أخطاء (Sentry أو GlitchTip)، تدوير سجلات Docker، **تنبيه عند فشل المهام أو النسخ الاحتياطي أو امتلاء القرص**؛ والمقاييس لاحقاً.
- **Cloudflare:** قواعد WAF وحماية من الروبوتات وتحديد معدّل إضافي على `/auth/*`؛ ومراعاة حد حجم الرفع (نحو 100MB حسب الخطة).
- **السيرفر:** تحديثات أمنية تلقائية، SSH بالمفاتيح فقط، جدار ناري يغلق ما لا يلزم.

## 20. الواجهة الأمامية

1. **الأساس:** Vite SPA، إعداد وقت التشغيل من `/config.json`، مخططات Zod مشتركة، تحديث توكن بمسار واحد (single-flight) مع تسجيل خروج متزامن بين التبويبات (`BroadcastChannel`).
2. **التنسيق:** خصائص CSS **منطقية فقط** (`inline-start/end`…) بقاعدة stylelint، خطوط عربية ذاتية الاستضافة، الأرقام والتواريخ من الإعدادات، المال **نص عشري**، التواريخ التقويمية `YYYY-MM-DD` نصاً، العرض الهجري عبر `Intl` (`islamic-umalqura`) والإدخال الهجري لاحقاً.
3. **الحالة:** TanStack Query بمصانع مفاتيح (key factories) وصلاحية بيانات حسب نوعها، لا إعادة محاولة عند 4xx، تفاؤلي للحالات الآمنة فقط؛ الفلاتر في الـ URL؛ `Idempotency-Key` لكل محاولة إرسال؛ `useJob` للمهام؛ `VERSION_CONFLICT` يحتفظ بقيم المستخدم.
4. **النماذج:** React Hook Form + Zod، و`DynamicForm` واحد مع `buildZodFromFields` المشترك؛ الحقول الحساسة مقنّعة مع «إظهار» مدقَّق؛ حارس تغييرات غير محفوظة؛ لا تخزين محلي للحقول الحساسة؛ التغييرات المؤرَّخة كخط زمني «إضافة تغيير بتاريخ سريان وسبب».
5. **الصلاحيات:** `usePermission` + كائن `can`؛ إخفاء مقابل تعطيل مع سبب؛ ترويسة `X-Permissions-Version`؛ خمول 30 دقيقة للخروج؛ **step-up** (~10 دقائق) لاعتماد/قفل/إعادة فتح الرواتب والتصدير الحساس وإظهار الحقول الحساسة.
6. **الجداول:** ترقيم وترتيب وفلترة من الخادم بحالة في الـ URL؛ virtualization لجداول الـ cursor؛ تعريفات فلاتر مشتركة؛ تخصيص الأعمدة والكثافة في إعدادات المستخدم؛ تحديد جماعي (الصفحة أو كل نتائج الفلتر)؛ إجماليات من `meta.summary`؛ شبكة خفيفة خاصة قابلة للتعديل مع لصق من Excel (حضور، مدخلات رواتب، معاينة الاستيراد)؛ الخدمة الذاتية للموبايل أولاً والإدارة للديسكتوب/التابلت؛ أنماط طباعة.
7. **الشاشات:** قائمة جانبية تُبنى من الصلاحيات، بحث عام (يشمل المراجع الخارجية)، إشعارات، مبدّل نطاق؛ لوحات حسب الدور؛ بطاقة موظف بتبويبات (تحميل عند الفتح)؛ شجرة هيكل؛ حضور (لوحة يومية، تقويم، شبكة يدوية، معالج استيراد، تصحيحات)؛ إجازات (تقويم فريق، نموذج برصيد حي)؛ صندوق موافقات موحد؛ رواتب كمعالج خطوات مع «كيف حُسب؟» وشارة «يدوي» ومحاكاة ومقارنة؛ مدير قوالب؛ مركز تقارير؛ إعدادات (أنواع الوثائق، الأنظمة الخارجية، ملفات الاستيراد، مصفوفة الأدوار، التدقيق، المهام)؛ `/me`.
8. **الأداء والنشر:** ميزانية حجم الحزمة في CI، ملفات ببصمة المحتوى و`index.html` بلا cache، إشعار «إصدار جديد» دون فرض إعادة تحميل، تقديم الملفات من Nginx مع brotli، PWA لاحقاً.
9. **الموبايل:** PWA للخدمة الذاتية أولاً، ثم **Expo (React Native)** للحضور (GPS + QR) بمشاركة `packages/shared`. متطلبات الخادم: توكن بـ `Authorization` للموبايل، ربط `device_id` بالجلسة، QR ديناميكي HMAC قصير العمر مع تحقق الموقع في الخادم.
