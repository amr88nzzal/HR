- كل الشرائح الوظيفية تعمل من الواجهة إلى القاعدة، بالصلاحيات والنطاق والتدقيق.

- التهجيرات تعمل على قاعدة فارغة وعلى نسخة ببيانات، دون كسر الوحدات السابقة.
- OpenAPI محدَّث، والترجمة (عربي/إنجليزي) كاملة، وRTL سليم.
- CI أخضر (أنواع، lint، اختبارات، فحص ثغرات)، والنشر على Staging ناجح.
- تحديث هذه الوثيقة (الحالة والملاحظات) و`DESIGN.md` إن تغيّر تصميم.

- **الواجهة:** قائمة الموظفين، بطاقة موظف بتبويبات (بيانات، وظيفة، رواتب لاحقاً، أرشيف، مراجع خارجية)، خط زمني للتغييرات، الهيكل التنظيمي (شجرة)، منشئ أنواع الوثائق، شاشة الأنظمة الخارجية، **استيراد الموظفين** (معالج Dry Run).
- بحث عام يشمل المراجع الخارجية.

**معيار القبول:** استيراد 200 موظف من Excel بتقرير أخطاء؛ نقل موظف بين قسمين بتاريخ سريان يحفظ التاريخ؛ نوع وثيقة جديد بحقول مخصصة يظهر في الأرشيف مع تذكير؛ بحث برقم المحاسبة يجد الموظف.

**الحالة:** 🟦 قيد التنفيذ (6 طلبات: 2a الموظفون والجداول الفرعية ← 2b العقود والتعيين الزمني ← 2c المراجع الخارجية والحقول المخصصة ← 2d الأرشيف والملفات ← 2e الشاشات ← 2f الاستيراد)
**تاريخ البدء / الانتهاء:** 2026-10-05 / —
**ملاحظات التنفيذ:**
- 🟦 **2a (الموظفون) جاهز للمراجعة:** تهجير `employees_core` (employees + contacts/addresses/dependents/bank_accounts/education/experience + numbering_sequences) مع RLS وتدقيق. رقم وظيفي تلقائي ذري بصيغة قابلة للضبط (`EMP-{seq:5}` افتراضياً، تتخطى الأرقام اليدوية) والتحديد اليدوي بصلاحية `set_number`. بحث عربي مطبَّع (`normalizeSearch` مشترك) بفهرس trigram. IBAN مشفّر AES-256-GCM (المفتاح ضمن الحمولة وAAD يربطه بالعمود) مع بصمة HMAC وقناع، لا يُعاد ولا يُدقَّق إلا مقنّعاً، والكشف بصلاحية مستقلة ومدقَّق دائماً. نطاق الذات يعمل؛ نطاقات الفرع/القسم/الفريق تُضاف في 2b (تُرفض مؤقتاً أماناً). ربط حساب مستخدم (ربط موجود أو إنشاء حساب بدور «موظف» بنطاق الذات). دور «موظف» الافتراضي يقرأ سجله (للشركات الجديدة؛ القائمة تعدّله يدوياً).
- 🟦 **2b (العقود والتعيين الزمني) جاهز للمراجعة:** تهجير `employments` (contracts, change_reasons, employments, employment_changes + دالة `company_today`). `EXCLUDE USING gist` يمنع تداخل التعيينات، وعقد نشط واحد للموظف، ومفتاح أجنبي مركّب يمنع قسماً غير متاح في الفرع (يُفحص أيضاً بالكود برسالة أوضح). `POST /employees/:id/changes` لسبعة أحداث: تعيين/إعادة تعيين، نقل، ترقية، تغيير مدير (كل منها يغلق القديم بيوم قبل السريان ويفتح جديداً فيبقى التاريخ كاملاً)، إيقاف، إعادة تفعيل، إنهاء (يغلق التعيين والعقد النشط). `GET /employees/:id/employments` و`/changes` (خط زمني بأسماء الفروع/الأقسام/المدير والسبب)، `/contracts` CRUD، `/change-reasons` CRUD، ويحمل `GET /employees` الفرع/القسم/المسمى/المدير الحاليين مع مرشحي `branchId` و`departmentId`. نطاقات الصلاحية على الموظفين صارت كاملة من التعيين الحالي: فرع، قسم، فريق (المرؤوسون المباشرون، نطاق جديد `team` بلا معرّف)، ذات.
- ⚠️ قيود معروفة: تغييرات الحالة (إيقاف/إنهاء) بتاريخ مستقبلي مرفوضة حتى المهام الخلفية (المرحلة 3)؛ نطاق القسم لا يشمل الأقسام الفرعية بعد؛ لا فحص لحلقات سلسلة المديرين. الأدوار الافتراضية الجديدة (مدير مباشر/موظف يقرآن التعيين) تُبذر للشركات الجديدة فقط، وللقائمة تُعدَّل يدوياً.
- 🔧 إصلاح: أعمدة `DATE` كانت تُرجَع كـ `Date` بمنطقة زمنية (تحوّل تاريخ الميلاد)، صارت نصاً `YYYY-MM-DD` في كل الـ API.
- ⚠️ **متغيرات بيئة جديدة إلزامية على السيرفر:** `ENCRYPTION_KEYS` و`ENCRYPTION_KEY_ID` و`ENCRYPTION_DIGEST_KEY` (انظر README). فقدان المفاتيح = فقدان البيانات المشفّرة.
