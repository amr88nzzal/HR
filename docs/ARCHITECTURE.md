# دليل المعمارية للمطوّر: نظام إدارة شؤون الموظفين (HRMS)

> هذا الدليل للمطوّر الجديد: يشرح كيف تتصل الأجزاء ببعضها وأين تجد كل شيء وكيف تضيف ميزة دون كسر القواعد.
> التفاصيل والمبررات الكاملة في `DESIGN.md`، والقواعد الملزمة في `CONVENTIONS.md`، والخطة في `PLAN.md`، والتشغيل في `RUNBOOK.md`.

---

## 1. الصورة العامة

```
المتصفح (React) ──► Nginx (gateway) ──► API (Express 5) ──► PostgreSQL (RLS)
                                             │
                                             └──► Worker (pg-boss) للمهام الخلفية: بريد، استيراد، صيانة الإجازات، تلخيص
```

- **مونوريبو (pnpm):** `apps/api` الخادم، `apps/web` الواجهة، `packages/shared` المخططات والأنواع والحسابات المشتركة، `infra/` الحاويات.
- **API-first:** الواجهة مجرد عميل للـ API (كل شيء تحت `/api/v1`)، والموبايل لاحقاً سيستعمل الـ API نفسه.
- **شركة واحدة الآن، وجاهز لعدة شركات:** كل جدول بيانات يحمل `company_id` ويحميه RLS.

## 2. أين أجد ماذا؟

| المسار | المحتوى |
|---|---|
| `apps/api/src/app.ts` | تركيب الـ middleware والمسارات (ترتيب التركيب مهم: الأخصّ أولاً) |
| `apps/api/src/modules/<وحدة>/` | كل وحدة: `*.routes.ts` (HTTP) و`service/ledger/engine` (المنطق) و`index.ts` (الواجهة العامة) و`*.integration.test.ts` |
| `apps/api/src/approvals/` | محرك الموافقات المشترك |
| `apps/api/src/jobs/` و`worker.ts` | الطابور والمهام المجدولة |
| `apps/api/src/notifications/` | الإشعارات والبريد وتيليجرام |
| `apps/api/src/db/` | الاتصال، `tenant.ts` (سياق الشركة)، `types.ts` (أنواع الجداول) |
| `apps/api/migrations/` | تهجيرات SQL مرقّمة (لا تُعدَّل بعد دمجها، تُضاف تهجيرة جديدة) |
| `apps/api/src/seed/` | بيانات تجريبية (`seed-demo`) لكل مرحلة |
| `packages/shared/src/` | مخططات Zod وحسابات نقية تُستعمل في الخادم والواجهة معاً |
| `apps/web/src/features/<وحدة>/` | شاشات كل وحدة، و`components/` عناصر مشتركة، و`i18n/` الترجمة (ar/en) |

وحدات الخادم: `identity` (دخول وأدوار وصلاحيات)، `org` (هيكل الشركة)، `employees`، `attendance`، `leave`، `payroll`، `admin-actions` (الإجراءات الإدارية)، `letters` (الوثائق الصادرة)، `archive`، `brand`، `reports`، `dashboard`، `table-prefs`.

## 3. دورة الطلب

1. `requestIdMiddleware` يعطي الطلب معرّفاً، ثم `authenticate` يتحقق من التوكن ويبني `req.auth` (المستخدم والشركة والصلاحيات الممنوحة ونطاق كل صلاحية).
2. `requirePermission('وحدة.مورد.فعل')` يمنع من لا يملك الصلاحية (403).
3. `makeRun(db)` / `withTenant` يفتح **معاملة** ويضبط `app.company_id` و`app.user_id` لها وحدها، ثم يمرّر `ctx = { trx, companyId, userId, requestId }` لكل دالة منطق.
4. السياسات (RLS) في PostgreSQL تحجب أي صف ليس لشركة المعاملة، حتى لو نسي الكود شرط `company_id`.
5. أي خطأ متوقع يُرمى كـ `AppError(code, status, message)` ويحوّله معالج الأخطاء إلى استجابة موحّدة.

**قاعدة ذهبية:** كل قراءة/كتابة للقاعدة تمر عبر `ctx.trx`، ولا يُنشأ اتصال خارج `withTenant`.

## 4. الصلاحيات والنطاق

- كتالوج الصلاحيات في `modules/identity/catalog.ts` بصيغة `الوحدة.المورد.الفعل`. تتزامن مع القاعدة عند التشغيل.
- الأدوار الجاهزة (`admin`, `hr_manager`, `hr_officer`, `manager`, `employee`) تُمنح صلاحياتها **عند إنشاء الدور فقط**؛ الصلاحية الجديدة تحتاج منحاً يدوياً للأدوار القائمة (المدير `admin` يتزامن تلقائياً).
- لكل منح **نطاق**: شركة، فرع، قسم، فريق (المرؤوسون المباشرون)، أو ذات. دالة `employeeScope(auth, الصلاحية)` ترجع شرط SQL يُضاف لأي استعلام على الموظفين، و`assertEmployeeVisible` للموظف الواحد (تُرجع 404 كي لا تكشف وجوده).
- اختبار `security.integration.test.ts` يمرّ على **كل المسارات** ويتحقق أنها محمية؛ المسار الذي يكفيه تسجيل الدخول فقط يُضاف صراحة إلى قائمة `AUTH_ONLY`.

## 5. المحركات الأساسية

### الحضور (`modules/attendance`)
سجلات خام (استيراد أو يدوي) ← `engine.ts` (دالة نقية) تحسب لكل يوم: الحالة، دقائق العمل والتأخير والمغادرة المبكرة والإضافي ← تُخزَّن في `attendance_days`. التعديل اليدوي (تصحيح/تجاوز) موثّق بالسبب والمستخدم. الفترات المقفلة لا تتغير بعد الآن.

### الإجازات (`modules/leave`)
**دفتر قيود (ledger)** لا رصيداً يُعدَّل: كل تغيير قيد (استحقاق، استهلاك، تعديل، ترحيل، انتهاء). الرصيد مجموع القيود، والخصم FIFO من أقدم دفعة. الدوال العامة: `debit` و`adjust` و`restore` و`balancesOf`. الدقة بالسنت (رقمان عشريان). طلب الإجازة يمر بمحرك الموافقات.

### الرواتب (`modules/payroll`)
- **`engine.ts` دالة نقية** (بلا قاعدة بيانات): من الراتب الأساسي والمكوّنات والمتغيرات تنتج بنود القسيمة والمجاميع، بـ `decimal.js` وتقريب لكل بند.
- **`calc.ts`** يجمع المدخلات من القاعدة: المتغيرات (أيام العمل، التأخير، المغادرة المبكرة، نقص الدوام…)، مكوّنات الموظف، بنود آلية (إجراءات إدارية، نقص دوام)، ثم يشغّل المحرك ويحفظ القسيمة. **بنود القسيمة تُعاد بناؤها كل احتساب**؛ لذلك يُحفظ التجاوز اليدوي منفصلاً ولا يضيع.
- **الأقساط (السلف)** عمود مستقل بعد الصافي (`loans_amount`, `payable_amount`) وليست بنداً داخل الصافي.
- **دورة الدورة:** مسودة (`draft`) ← احتساب (يتكرر) ← اعتماد (`approved`، تُنشأ الدفعات) ← قفل (`locked`، تُثبَّت الأقساط وخصومات الرصيد والإجراءات الإدارية). إعادة الفتح تعكس هذه الآثار بسبب مسجّل. أثر الإجراء الإداري/نقص الدوام/القسط يُطبَّق عند **القفل** ويُعكس عند **إعادة الفتح**.
- **نقص الدوام (`shortfall.ts`):** سياسة قابلة للضبط (دقائق مع سماحية أو شرائح) + قرار المدير لكل موظف/شهر (راتب، رصيد إجازات، تقسيم، إعفاء). عند عدم كفاية الرصيد يُخصم المتاح والباقي من الراتب مع تحذير.

### الموافقات (`approvals/`)
محرك واحد لكل أنواع الطلبات (إجازة، تصحيح حضور، عمل إضافي، إجراء إداري…): مسارات مضبوطة بسجل (`registry.ts`) وتفويضات. كل نوع طلب يسجّل «معالجاً» ينفَّذ عند الاعتماد أو الرفض.

### المهام الخلفية (`jobs/`)
`pg-boss` فوق PostgreSQL (لا Redis). التعريفات في `definitions.ts`، والجدولة بـ cron في `runtime.ts`. الحاوية `worker` تنفّذها منفصلة عن الـ API.

## 6. نمط الكود المتكرر

- **الحسابات المشتركة تُكتب نقية في `packages/shared`** (مثل `computeShortfall` و`planDefer` و`evalFormula`) فتُختبَر بسرعة وتُستعمل في الواجهة للمعاينة وفي الخادم للتنفيذ بالنتيجة نفسها.
- **المخططات:** كل مدخل API له مخطط Zod في `packages/shared`، يُحلَّل به الطلب في الخادم وتُبنى به النماذج في الواجهة.
- **المال والأرقام:** نصوص عشرية و`decimal.js`، ولا `number` للمبالغ.
- **التسمية:** `snake_case` في القاعدة و`camelCase` في الكود (تحويل تلقائي في Kysely). استعلامات `sql` الخام يعيد لها المحوّل الأسماء `camelCase` أيضاً.
- **القوائم:** ترقيم صفحات من الخادم (`page`, `pageSize`) وفرز وفلاتر متعددة القيم (`a,b,c`).
- **التجاوز اليدوي** لأي ناتج محسوب يجب أن يكون موثّقاً (من، متى، لماذا).

## 7. إضافة ميزة جديدة: قائمة تحقق

1. **تهجيرة SQL** جديدة: الجداول مع `company_id` وسياسة RLS (`tenant_isolation`) ومشغّلات `updated_at` والتدقيق، ثم تحديث `db/types.ts`.
2. **مخططات Zod** في `packages/shared` وتصديرها من `index.ts`، مع اختبار وحدة للحسابات النقية.
3. **الخادم:** منطق في ملف الوحدة، ومسارات في `*.routes.ts` بـ `requirePermission`، وتطبيق نطاق الموظفين (`employeeScope`) حيث يلزم، وتركيب الراوتر في `index.ts` الخاص بالوحدة.
4. **الصلاحيات:** إضافتها في `catalog.ts`، وتذكّر أن الأدوار القائمة تحتاج منحاً يدوياً (اذكر ذلك في وصف الـ PR).
5. **اختبارات تكامل** تغطي: الصلاحيات (403)، المسار السعيد، الحالات الحدّية، وأثر الميزة على الرواتب/الأرصدة إن وُجد. شغّلها محلياً (انظر `README.md`).
6. **الواجهة:** صفحة في `features/<وحدة>`، مسار في `routes.tsx` وعنصر قائمة إن لزم، ونصوص عربية وإنجليزية في `i18n`.
7. **البيانات التجريبية:** طبقة في `seed-demo` + تحديث `demo.integration.test.ts` وقسم README.
8. **التوثيق:** تحديث `PLAN.md` و`USER-GUIDE.md`، والتعليقات العربية على الأجزاء الحساسة.
9. قبل الدمج: `pnpm prettier --write`, `pnpm lint`, `pnpm -r typecheck`, الاختبارات كاملة.

## 8. الاختبار

- **وحدة (Vitest):** للدوال النقية في `packages/shared` وللمحركات (`engine.test.ts`).
- **تكامل (Vitest + PostgreSQL حقيقي + Supertest):** `*.integration.test.ts` تنشئ قاعدة مؤقتة لكل ملف وتختبر عبر الـ API الحقيقي.
- **الواجهة:** Vitest مع `testing-library` وتقليد الـ API.
- **CI (GitHub Actions):** `verify` (lint وأنواع ووحدة) و`integration` و`docker` (بناء الصور). تعثّر `docker` بعد ثوانٍ غالباً سحبٌ فاشل للصورة الأساسية؛ يكفي إعادة تشغيل المهمة.

## 9. مصطلحات

| المصطلح | المعنى |
|---|---|
| RLS | أمان على مستوى الصف في PostgreSQL، يعزل بيانات كل شركة |
| `ctx` | سياق المعاملة والشركة والمستخدم الممرَّر لكل دالة منطق |
| نطاق (scope) | حدّ ما يراه المستخدم بصلاحية معيّنة: شركة/فرع/قسم/فريق/ذات |
| دورة الرواتب | شهر رواتب لمجموعة دفع: مسودة ← معتمدة ← مقفلة |
| نقص الدوام | مجموع دقائق التأخير والمغادرة المبكرة المحتسبة بالسياسة |
| دفتر القيود | سجل تغيّرات رصيد الإجازات الذي يُشتق منه الرصيد |
