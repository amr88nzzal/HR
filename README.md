# HRMS — نظام إدارة شؤون الموظفين

مونوريبو (pnpm): `apps/api` (Express 5 + TypeScript)، `apps/web` (Vite + React)، `packages/shared` (أنواع ومخططات Zod مشتركة)، `infra/` (Docker وNginx).

- **التصميم والمعايير والخطة:** `docs/DESIGN.md` · `docs/CONVENTIONS.md` · `docs/PLAN.md` (تُحدَّث عند انتهاء كل مرحلة). **للمطوّر الجديد ابدأ بـ** `docs/ARCHITECTURE.md`.
- **النموذج الأولي القديم:** `reference/prototype/` (للرجوع فقط؛ لا يُشغَّل ولا يُبنى عليه).

## التطوير

```bash
corepack enable
pnpm install
cp .env.example .env        # عدّل القيم
pnpm dev:api                 # http://localhost:3000/health/live
pnpm dev:web                 # http://localhost:5173
pnpm typecheck && pnpm lint && pnpm test
```

## التشغيل بـ Docker

```bash
cp .env.example .env         # عدّل: POSTGRES_PASSWORD و APP_DB_PASSWORD و JWT_SECRET ومفاتيح التشفير (ENCRYPTION_*)
docker compose -f infra/docker-compose.yml --env-file .env up -d --build
```

مفاتيح التشفير (مرة واحدة، واحفظ نسخة منها خارج الخادم):

```bash
echo "ENCRYPTION_KEYS=k1:$(openssl rand -base64 32)"
echo "ENCRYPTION_KEY_ID=k1"
echo "ENCRYPTION_DIGEST_KEY=$(openssl rand -base64 32)"
```

الملفات المرفوعة (الأرشيف وصور الموظفين) تُحفظ في volume باسم `filesdata` (`/data/files` داخل الحاوية). انسخه احتياطياً مع قاعدة البيانات، وتحتاج الملفات المشفّرة المفاتيح نفسها أعلاه.

أنشئ أول مدير (مرة واحدة؛ كلمة المرور تُمرَّر بمتغير بيئة لا بسطر الأوامر):

```bash
docker compose -f infra/docker-compose.yml --env-file .env run --rm \
  -e ADMIN_PASSWORD='كلمة-مرور-طويلة-وغير-شائعة' migrate \
  node dist/cli.js create-admin --email admin@example.com --name "المدير" --company-name "اسم الشركة"
```

أوامر أخرى: `post-migrate` (تلقائي عند كل نشر)، `reset-password --email ...`.

### بيانات تجريبية (للتجربة والعرض فقط)

بعد `create-admin` يمكن بذر شركة ببيانات تجريبية تغطي كل ما نُفّذ حتى الآن (قاعدة العمل: كل مرحلة جديدة تُضيف طبقتها هنا قبل اعتبارها منتهية):

- **الأساس:** فرعان وخمسة أقسام ودرجات ومسميات ومراكز تكلفة و30 موظفاً (`DEMO-001`…) بسلاسل مديرين وتعيينات وعقود وجهات اتصال وأكواد محاسبة/بصمة، وثلاثة مستخدمين (`demo.hr@demo.hrms.local` مدير موارد بشرية، `demo.manager@…` مدير مباشر، `demo.employee@…` موظف).
- **تفاصيل الموظفين:** عناوين وجهات طوارئ ومعالون وتعليم وخبرات وحسابات بنكية (مشفّرة) وحقول إضافية بينها حقل حساس (الرقم الوطني)، وعملة أساسية JOD.
- **أحداث وظيفية:** نقل وترقية وتغيير مدير وإيقاف وإعادة تفعيل وإنهاء خدمة.
- **الأرشيف:** أنواع وثائق (هوية/إقامة للموظفين، رخصة المنشأة، عقد إيجار الفرع) و17 وثيقة بتذكيرات متأخرة وقريبة وبعيدة (تغذّي الملخص اليومي).
- **الموافقات:** سلسلة عامة بخطوتين (الثانية مشروطة بالمبلغ ≥ 1000) وتفويض، وسبعة طلبات بكل الحالات (معلّق، موافَق، مرفوض، مُرجَع، مسحوب) مع إشعاراتها، ومستخدم إضافي `demo.ceo@…` للمدير العام.
- **الإجازات:** ثلاثة أنواع (سنوية، مرضية مرفقها مطلوب، بلا راتب) وثلاث سياسات (21 يوماً للجميع، 30 يوماً للمدير بربط على مستوى الموظف، 14 مرضية مقدَّمة)، وعطل رسمية، واستحقاق السنة الماضية والحالية مع ترحيل بالسقف وانتهاء المرحَّل، وطلبات بكل الحالات (معلّق، معتمد، مرفوض، مسحوب، معتمد ثم ملغى، نصف يوم، تمرّ بعطلة، مرضية، بلا راتب، وطلب للمدير) وتعديلان يدويان من الموارد البشرية. وتظهر كلها في تقويم الفريق وتقرير الأرصدة. جرّبها بـ `demo.employee@…` (طلباتي وأرصدتي) و`demo.manager@…` (صندوق الموافقات) و`demo.hr@…` (كل الطلبات والأرصدة).
- **الحضور (الجداول):** ثلاث ورديات (صباحية، مقسومة بفترتين، ليلية تعبر منتصف الليل) وثلاثة جداول أسبوعية (الأحد–الخميس عمل والجمعة والسبت راحة) وتعيينات بالأخص: القياسي للشركة، والمقسوم لقسم المبيعات، والليلي لموظف واحد (`DEMO-010`) لشهرين.
- **الحضور (البصمات):** بصمات آخر أسبوعين لموظفي التجربة: التزام وتأخير وخروج مبكر وغياب، ووردية ليلية لـ `DEMO-010`، ثم الاحتساب مع يوم غياب واحد عليه تجاوز يدوي مفتوح (ملاحظة «عطل في جهاز البصمة»).
- **الحضور (الاستيراد):** ملف استيراد افتراضي `DEMO-DEVICE`، ومراجع جهاز لستة موظفين، ودفعة مطبَّقة من ملف CSV (قبل أسبوعين تقريباً) فيها رمزان غير مربوطين (`9001`، `9002`) محجوزان لتجربة «ربط المحجوز بموظف».
- **الحضور (التعديلات والإضافي):** لـ `demo.employee@…`: أربعة تعديلات حضور (طلب معتمد، طلب معلّق، طلب مرفوض، وتعديل مباشر من الموارد البشرية) وأربعة طلبات عمل إضافي (لاحق معتمد 120 دقيقة محتسبة، لاحق مرفوض يبقى فائضه مسجلاً بلا احتساب، لاحق معلّق، ومسبق معلّق ليوم قادم). المعلّقة تظهر في صندوق موافقات المدير (`demo.manager@…`) وتُجرَّب منه، وكل القوائم في «تعديلات وإضافي» لـ `demo.hr@…`. طريقة التعديل (طلب/مباشر/كلاهما) ومهلة الموظف (14 يوماً) من الإعدادات.
- **الوثائق الصادرة (القوالب):** قالبا شهادة عمل عربي وإنجليزي (`DEMO-CERT-AR`/`DEMO-CERT-EN`) لكل منهما إصدار مفعّل وآخر مسودة بجدول، لتجربة المحرر والمعاينة والتفعيل والتراجع. إصدار الـ PDF نفسه يحتاج حاوية `render` (تُبنى مع compose، وتتضمن LibreOffice لقوالب DOCX) وصلاحية `letters.document.issue`. قوالب DOCX لا تُبذر (تحتاج ملفاً مخزَّناً): ارفع ملف Word من «قالب جديد ← ملف Word (DOCX)».
- **الرواتب (الهيكل):** أساسان (`demo_insurable`, `demo_taxable`)، وسبعة مكونات (سكن ومواصلات وعمل إضافي وضمان الموظف والشركة وضريبة بجدول نسب وخصم غياب)، وجدول ضريبة توضيحي `demo_tax` (أرقام توضيحية لا قانون)، وهيكلان، وراتب لكل موظف تجريبي بخط زمني (وزيادة سابقة وحالية لموظفين اثنين). تُجرَّب من «إعداد الرواتب» ومن تبويب «الراتب» في بطاقة الموظف (صلاحيات `payroll.*` لمدير الموارد/النظام).
- **الرواتب (الدورات):** مجموعة الدفع الافتراضية الشهرية، وسببا تجاوز يدوي (`demo_correction`, `demo_agreement`)، ودورة مسودة للشهر الأخير المكتمل محتسبة بقسائمها (تُجرَّب من «دورات الرواتب»: القسيمة و«كيف حُسب؟» والتجاوز اليدوي والمحاكاة والاعتماد). صلاحيات `payroll.period/payslip/input` لمدير الموارد/النظام.
- **الرواتب (السلف والدفعات):** ثلاث سلف تجريبية (قرض بستة أقساط وسلفة بقسط واحد وقرض كبير يتجاوز سقف الصافي فيُرحَّل) بجداول أقساطها ودفعات صرفها، وتظهر أقساطها في عمود مستقل «قسط السلف» ثم «المستحق للدفع» في كشف الدورة المسودة. تُجرَّب من «قروض وسلف» وتبويب «السلف» في بطاقة الموظف؛ وبعد اعتماد الدورة تظهر تبويبة «الدفعات» (تعليم مدفوعة وتصدير CSV). صلاحيات `payroll.loan/payment` لمدير الموارد/النظام، والسقف من الإعدادات (`loanMaxNetPercent`، افتراضياً 50%).
- **الإجراءات الإدارية:** تسعة أنواع افتراضية (تنبيه/إنذارات مع التصعيد/خصم/إيقاف/مكافآت/شكر/ترقية) وسبعة إجراءات بحالات مختلفة (معتمدة، مسودة، ملغاة، وإنذار مُقَرّ به). تُجرَّب من «الإجراءات الإدارية» (قائمة بفلاتر متعددة وإضافة وتفاصيل وإلغاء بسبب) و«أنواع الإجراءات»، ومن «سجلّي الإداري» يُقرّ الموظف بالاستلام. بلا أثر مالي عمداً.
- **الهوية البصرية:** نصوص ترويسة وتذييل تجريبية بلغتين (اسم قانوني وعنوان وهاتف وبريد وموقع ورقم ضريبي وسجل تجاري) وتفعيل الترويسة التلقائية على قالبي شهادة العمل التجريبيين. **الشعارات لا تُبذر**: ارفعها من «الإدارة ← الهوية البصرية» (PNG/JPG/SVG حتى 1MB، شعار لكل لغة ونسخة داكنة وختم) وتابع المعاينة الحيّة بالعربية والإنجليزية، ثم أصدر شهادة عمل من بطاقة موظف لترى الترويسة. صلاحيتا `org.brand.read/update`.
- **حساب مدعو (U):** موظف تجريبي واحد بلا حساب يُنشأ له حساب `demo.invited@demo.hrms.local` بحالة «مدعو» (تبويب «الحساب» في بطاقته، ومنه «إعادة إرسال الدعوة» ثم فتح الرابط وتعيين كلمة المرور). إنهاء خدمة موظف مرتبط بحساب يعطّل حسابه تلقائياً ويرفع التعطيل عند إعادة التعيين.
- **تاريخ ستة أشهر:** يُضاف تلقائياً مع `seed-demo`: بصمات الحضور لستة أشهر (تأخير وغياب وخروج مبكر، مع شهر أسوأ للتباين وتجاوز العطل والإجازات)، وإجازات تاريخية معتمدة ومرفوضة للمستخدمين التجريبيين الأربعة، وستة أشهر رواتب (خمس دورات مقفلة ومسودة) بدفعات مدفوعة ومعلّقة، وقرض مسدَّد بأقساطه المخصومة. كل جزء آمن لإعادة التشغيل.
- **القسائم (7d):** دورة رواتب **مقفلة** قبل الدورة التجريبية: قسائمها تظهر في «قسائم راتبي» للموظف المرتبط بحساب (أرقام مخفية حتى «إظهار»)، ويمكن تنزيل PDF لكل قسيمة وZIP للدورة من شاشة الدورة، وتقارن الدورة التجريبية بها بفروق البنود. (`payslips`)
- **التقارير (8):** تخطيط أعمدة افتراضي «DEMO عرض مختصر» لقائمة الموظفين لمستخدمين تجريبيين، يظهر في «التقارير». (`reports`)

كلمة مرور المستخدمين من `DEMO_PASSWORD`. الأمر آمن لإعادة التشغيل **ويُحدّث قاعدة بُذرت سابقاً**: كل طبقة لها علامة فتُضاف الناقصة فقط دون حذف أو تعديل ما هو موجود. حسابات البنك والحقل الحساس تحتاج مفاتيح `ENCRYPTION_*` (تمرّرها compose لخدمة `migrate` من `.env` تلقائياً).

```bash
git pull
docker compose -f infra/docker-compose.yml --env-file .env up -d --build
docker compose -f infra/docker-compose.yml --env-file .env run --rm \
  -e DEMO_PASSWORD='كلمة-مرور-تجريبية-طويلة' migrate \
  node dist/cli.js seed-demo --company main
```

لا تشغّله على قاعدة إنتاج حقيقية؛ لإزالتها احذف الـ volume وأعد التهيئة (`down -v`) أو احذف سجلات `DEMO-` يدوياً.
التطبيق يتصل بدور `hrms_app` (غير مالك) فتُطبَّق سياسات RLS؛ المالك للترحيل والـ CLI فقط.

> **تنبيه:** صورة PostgreSQL تقرأ `POSTGRES_USER` و`POSTGRES_PASSWORD` عند إنشاء الـ volume أول مرة فقط. إن غيّرتهما لاحقاً فنفّذ `docker compose ... down -v` (يمسح بيانات القاعدة!) أو غيّرهما داخل PostgreSQL نفسه.

## التهجيرات

ملفات SQL في `apps/api/migrations` (قسما `-- Up Migration` و`-- Down Migration`):

```bash
pnpm --filter @hrms/api migrate:create اسم_التهجير
DATABASE_URL=... pnpm --filter @hrms/api migrate up     # أو down
```

في Docker تعمل خدمة `migrate` تلقائياً قبل الـ API. اختبار التكامل (يتطلب Docker): `pnpm --filter @hrms/api test:integration`.
